أنماط الـ Compilers: من الـ asm للـ C بسرعة

أغلب الـ malware مكتوب بـ C/C++ ومتعمله compile بـ MSVC أو gcc أو clang. الـ compiler مش بيترجم سطر بسطر — ده بيعيد كتابة الكود كله. الـ reverser المحترف مش بيقرا instruction instruction؛ بيتعرف على الأنماط ويحوّل 10 أسطر asm لسطر C واحد في ثانية. المرحلة دي قاموس الأنماط دي.

طريقة القراية: Pattern → اسم → Collapse

(1) اعزل الـ blocks (الـ graph بيساعدك). (2) لكل block اسأل: ده idiom معروف؟ (loop، range check، bit test، struct copy…). (3) سمّيه في IDA (rename/comment) — is_lower، xor_decrypt. (4) اطوي التفاصيل ومتقراهاش تاني. الـ decompiler بيعمل جزء كبير من ده، بس هو اللي بيغلط في الـ idioms النادرة — وعشان كده لازم تقرا الـ asm بنفسك.

إزاي تعرف إن الكود متعمله compile بـ -O0؟ فيه vectorization كل متغير محلي ليه مكان على الـ stack ([rbp-…]) وبيتقرا ويتكتب منه في كل استخدام مفيش push rbp كل الدوال inline -O0 بيترجم سطر بسطر: load من الـ stack، عملية، store للـ stack. ممل بس سهل جدًا. فكّر في الـ tab بتاع gcc-O0 فوق. lea eax, [rdi+rdi*8] بتحسب: rdi + 8 عنوان في الذاكرة rdi × 8 x × 9 x + x×8 = 9x. الـ scale بيبقى 1/2/4/8، فـ lea بتعمل ×2، ×3، ×4، ×5، ×8، ×9 في instruction واحدة. base + index×scale… دالة فيها sar eax, 4 ودالة تانية فيها shr eax, 4 (الاتنين قسمة على 16). نستنتج إيه؟ الأولى على signed (ومحتاجة bias للسالب قبلها)، والتانية على unsigned الاتنين نفس الشيء الأولى أسرع الأولى 64-bit نوع الـ shift = نوع المتغير. ده من أهم مصادر معلومات الـ types وانت بتعمل reverse. sar = arithmetic (بيحافظ على الإشارة)، shr = logical. في آخر دالة: add rsp, 40 ثم jmp send_report (مش call). ده: bug loop tail call: return send_report(…) exception الدالة نضّفت الـ frame بتاعها وقفزت. send_report هترجع مباشرة للـ caller الأصلي. jmp لدالة تانية بعد تنظيف الـ stack… cmp ecx, edx ثم cmovb eax, ecx. نوع المتغيرات؟ signed int unsigned (b = below) float pointer بالضرورة a/b/ae/be = unsigned (أو pointers)، g/l/ge/le = signed. نفس قاعدة الـ jcc بالظبط. below ولا less؟ فيه mov eax, 10040h ثم call __chkstk ثم sub rsp, rax. ده معناه: anti-debug الدالة recursive الدالة عندها متغيرات محلية كبيرة (~64KB) — غالبًا buffer (زي buffer للملفات أو للـ network) heap allocation __chkstk = frame أكبر من 4KB على Windows. الحجم نفسه معلومة: buffer 64KB في دالة network = غالبًا buffer الاستقبال. __chkstk بتظهر لما الـ frame يعدّي صفحة. رجّع في eax = 1 لو edi بين '0' و'9'، وإلا 0. من غير jumps ولا cmov، ومقارنة واحدة بس (حيلة الطرح + unsigned). (انتبه: setcc بتكتب في al بس — صفّر eax قبلها.) is_digit: xor eax, eax ret is_digit: lea ecx, [rdi-'0'] ; c - '0' xor eax, eax ; clear BEFORE setcc (xor changes flags!) cmp ecx, 9 ; unsigned: 0..9 inside, everything else huge setbe al ret رجّع x / 16 بقواعد C (التقريب ناحية الصفر: ‎-100/16 = ‎-6) في eax، وx في edi (int). ممنوع div/idiv/mul/imul. (ممكن تعمل verify في المعمل: جرّب كل حرف.) الأوامر اللي بحرف واحد في الـ backdoors شائعة: d = download، k = kill، r = run… الكود ده بيحسب x % N (signed int في edi). قيمة N؟ mod_n: mov edx, edi sar edx, 31 shr edx, 28 lea eax, [rdi+rdx] and eax, 15 sub eax, edx ret and eax, 15 = and مع N−1، والـ bias (shr 28) = 15 للسالب. and 15 ⇐ N = 16. الـ sar 31 / shr 28 بيعمل bias = 15 لو x سالب و0 لو موجب، فالنتيجة بتطلع بإشارة x زي C (‎-37 % 16 = ‎-5).
