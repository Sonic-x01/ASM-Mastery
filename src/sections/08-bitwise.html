الـ Bits: AND وOR وXOR والـ Shifts والـ Rotates

التشفير البسيط، فك الـ strings، الـ API hashing، الـ checksums، الـ flags في الـ structs، الـ alignment — كلها bits. لو في sample لقيت loop فيها xor وrol — مبروك، غالبًا لقيت الـ decryption routine. المرحلة دي هتخليك تقراها وتكتبها وتعكسها.

العمليات المنطقية bit by bit

InstructionCالقاعدة لكل bitالاستخدام الكلاسيكي
and a, ba &= b1 لو الاتنين 1امسح bits / خد جزء: and eax, 0FFh = آخر byte
or a, ba |= b1 لو أي واحد 1شغّل bits: or eax, 4 = set bit 2
xor a, ba ^= b1 لو مختلفيناقلب bits، صفّر register، تشفير

كلهم (ما عدا not) بيعملوا CF = OF = 0 وبيظبطوا ZF وSF حسب النتيجة. عشان كده test eax, eax + je هو أشهر شكل لـ if (x == 0)، وtest eax, eax + js = if (x < 0).

🎭

الـ masks

set: x | (1<<n) · clear: x & ~(1<<n) · toggle: x ^ (1<<n) · test: x & (1<<n). في Windows هتشوف الـ flags دي في كل حاجة: PAGE_*، FILE_ATTRIBUTE_*، CREATE_SUSPENDED (= 4)… لما تشوف or ecx, 4 قبل CreateProcess = بيعمل process "suspended" — علامة process hollowing!

🔐

XOR = تشفير قابل للعكس

(x ^ k) ^ k = x. نفس العملية بتشفّر وبتفك. عشان كده أبسط وأشهر "تشفير" في الـ malware: single-byte XOR، multi-byte XOR key، أو XOR بـ key بيتغير (rolling). ضعيف جدًا كتشفير، بس كفاية يخبّي الـ strings من الـ strings tool والـ AV signatures.

🕵️
مش كل xor تشفير

xor eax, eax = تصفير. xor eax, edx مع cdq = abs. الـ XOR بتاع التشفير ليه شكل مميز: loop + xor byte ptr [reg+index], key (أو xor بين byte من الـ buffer وbyte من الـ key) + زيادة الـ index. أداة زي capa بتدور على النمط ده أوتوماتيك وبتقولك "encode data using XOR".

الـ Shifts والـ Rotates bits on the move

InstructionCملاحظة
shl eax, 3x << 3 = x * 8أسرع من الضرب
shr eax, 4x >> 4 (unsigned)= ÷16 للـ unsigned
sar eax, 4x >> 4 (signed)بيقرّب لـ −∞: −1 >> 4 = −1، مش 0! عشان كده x/16 في C محتاجة تصحيح
rol eax, 13(x << 13) | (x >> 19)الـ compilers بيتعرفوا على الـ pattern ده ويحوّلوه rol
shr rax, 63x < 0 (لو signed) / أعلى bitاستخراج bit الإشارة

الـ instruction اللي بتعملها هي اللي بتفضح النوع: shr ⇐ unsigned، sar ⇐ signed. وشوف الـ compiler بيعمل إيه مع شوية bit tricks — لاحظ إن MSVC كتب rol 13 على شكل ror 19 (نفس النتيجة بالظبط في 32-bit):

int is_pow2(unsigned x) { return x && !(x & (x - 1)); } unsigned rotl13(unsigned x) { return (x << 13) | (x >> 19); } int bit_set(unsigned flags, int n) { return (flags >> n) & 1; } unsigned to_upper(unsigned c) { return c & ~0x20u; } int sar_div4(int x) { return x >> 2; } bits: mov eax, 0b1011_0110 ; 0xB6 and eax, 0x0F ; keep low nibble -> 0x06 or eax, 0x80 ; set bit 7 -> 0x86 xor eax, 0x01 ; toggle bit 0 -> 0x87 test eax, 0x02 ; is bit 1 set? (ZF=0 -> yes) mov ebx, -16 ; 0xFFFFFFF0 sar ebx, 2 ; -16 >> 2 = -4 (sign kept) mov ecx, -16 shr ecx, 2 ; 0x3FFFFFFC (unsigned view) mov edx, 0x12345678 rol edx, 8 ; 0x34567812 ror edx, 8 ; back to 0x12345678 ret

فك تشفير XOR: الـ pattern الأشهر في الـ malware decoder loop

الـ string الحقيقية (URL الـ C2 مثلًا) متخزنة مشفّرة في الـ .data، والـ malware بيفكها في الذاكرة لحظة الاستخدام. ده decoder حقيقي الشكل — شغّله في المعمل وراقب الـ Memory pane والـ bytes بتتغير واحد ورا التاني:

default rel section .data blob: db 0x32, 0x2E, 0x2E, 0x2A, 0x60, 0x75, 0x75, 0x39, 0x68, 0x74 ; encrypted db 0x3F, 0x22, 0x3B, 0x37, 0x2A, 0x36, 0x3F, 0x74, 0x39, 0x35 db 0x37, 0x75, 0x3D, 0x3B, 0x2E, 0x3F, 0x74, 0x2A, 0x32, 0x2A, 0 BLOB_LEN equ 30 KEY equ 0x5A section .text global _start _start: lea rsi, [blob] ; rsi = pointer to the encrypted bytes xor ecx, ecx ; rcx = i = 0 .decode: xor byte [rsi+rcx], KEY ; blob[i] ^= 0x5A inc rcx cmp rcx, BLOB_LEN jb .decode ; while (i < 30) mov rdi, rsi call print_str ; now it is readable call print_nl xor edi, edi call exit

ونفس الـ loop لما الـ compiler يكتبها: gcc بـ -O1 طلّع loop صغيرة نضيفة، لكن MSVC بـ /O2 عملها vectorized: بيفك 64 byte في المرة بـ xorps على registers الـ xmm، وبعدين loop صغيرة للباقي. لما تلاقي الشكل التاني ده في sample — هو نفس الـ XOR decoder بالظبط.

void xor_decode(unsigned char *buf, int n, unsigned char key) { for (int i = 0; i < n; i++) buf[i] ^= key; }

API Hashing بـ ROR13 shellcode classic

الـ shellcode والـ malware المتقدم مش بيكتب أسماء الـ APIs ("VirtualAlloc") عشان متتمسكش. بدلها بيحسب hash لكل اسم في الـ export table بتاع الـ DLL، ويقارنه بـ hash ثابت في الكود. أشهر خوارزمية (من Metasploit والـ shellcode القديم): لكل حرف h = ror(h, 13) + c.

APIROR13 hash
LoadLibraryA0xEC0E4E8E

WinExec0x0E8AFE98

لو شفت أي رقم من دول في sample — اعرف فورًا هو بيدوّر على أنهي API. ومحللين كتير عندهم قواعد بيانات بالـ hashes (زي HashDB plugin لـ IDA). هتكتب الخوارزمية دي بنفسك في التحدي تحت، وهنستخدمها بجد في مرحلة الـ PEB walking.

Bit Test وBit Scan bt · bsf · bsr · popcnt

Instructionبتعمل إيه
bt eax, 5CF = bit رقم 5 (من غير ما تغيّر eax)
bts / btr / btcنفس الكلام + set / reset / complement للـ bit (bitmaps، الـ thread-safe flags مع lock)
bsf ecx, eaxecx = رقم أصغر bit = 1 (ZF=1 لو eax = 0 والـ destination مش بيتغير)
bsr ecx, eaxecx = رقم أكبر bit = 1 (= ⌊log₂ x⌋)
popcnt ecx, eaxعدد الـ bits اللي = 1
🔬
bt مع ثوابت ضخمة = switch مضغوط

لما تشوف mov rax, 0x2000100A + bt rax, rcx + jb، ده الـ compiler بيختبر "هل rcx واحد من مجموعة قيم" مرة واحدة: كل bit = قيمة مسموحة. ده شكل if (c == 1 || c == 3 || c == 12 || c == 29).

✏️ تمارين المرحلة 08

and eax, 0FFFFFFF0h بتعمل إيه؟ بتزوّد 16 بتمسح أول 4 bits ← بتقرّب eax لتحت لأقرب مضاعف لـ 16 بتقسم على 16 بتمسح أعلى 4 bits الـ mask ده كله 1 ما عدا آخر 4 bits. ده بالظبط الـ alignment: and rsp, -16 = اجعل الـ stack aligned على 16. 0xF0 في الآخر = 1111 0000. test al, 1 ثم jnz label. الشرط في C؟ if (al == 1) if (al > 0) if (al == 0) if (al & 1) — يعني لو الرقم فردي test بيعمل AND بالـ 1؛ النتيجة مش صفر لو آخر bit = 1 (فردي). test = AND من غير تخزين. jnz = لو النتيجة مش صفر. eax = -20. بعد sar eax, 2؟ −5 5 0x3FFFFFFB −20 sar بيحافظ على الإشارة: −20 ÷ 4 = −5 (وهنا مفيش باقي فمفيش مشكلة التقريب). sar = arithmetic shift للأرقام signed. eax = -1. بعد shr eax, 28؟ −1 0 15 (0xF) 0xFFFFFFF0 shr بيدخّل أصفار: 0xFFFFFFFF >> 28 = 0xF. shr مش بيهتم بالإشارة. في loop لقيت: movzx eax, byte ptr [rdx+rcx] ثم xor al, byte ptr [r8+r9] ثم mov [rdx+rcx], al وبعدين inc r9 وr9 بيرجع صفر كل ما يوصل 16. ده: نسخ buffer XOR decryption بمفتاح طوله 16 byte (repeating key) حساب طول string ضغط بيانات buffer[i] ^= key[i % 16]. ضع breakpoint بعد الـ loop وdump الـ buffer تشوف الـ plaintext — أو اقرا الـ 16 byte بتوع الـ key وفكها بنفسك بـ CyberChef. byte من buffer XOR byte من مكان تاني بيتلف كل 16. rol eax, 8 على 0xAABBCCDD؟ 0xBBCCDD00 0xDDAABBCC 0xBBCCDDAA 0x00AABBCC rotate left بـ byte: الـ AA اللي طلع من الشمال لف دخل يمين. rotate = shift بس اللي بيطلع بيدخل من الناحية التانية. قبل CreateProcessA لقيت الـ argument بتاع dwCreationFlags = 4. ده معناه: CREATE_SUSPENDED — الـ process هيتعمل والـ main thread واقف (علامة process hollowing / injection) Debug mode إخفاء الشباك أولوية عالية CREATE_SUSPENDED = 0x4. الـ malware بيعمل process شرعي (svchost مثلًا) suspended، يستبدل الكود جواه، وبعدين ResumeThread. سلسلة الـ APIs دي من أشهر الـ indicators. دوّر على CreationFlags في MSDN: قيمة 4 = ؟ ليه shl eax, 32 مش بتصفّر eax؟ بتصفّره عادي خطأ في الـ assembly عشان بتحرك 32 bit ناحية rax لأن العدد بيتعمله mask لـ 5 bits (32 & 31 = 0) — فمفيش shift خالص في 32-bit العدد = count & 0x1F. وده سبب إن x << 32 في C undefined behavior. العدد بيتقص قبل ما يتنفذ. الـ bytes دي متشفّرة بـ XOR بمفتاح متعدد طوله 4: 0x13, 0x37, 0xC0, 0xDE (الـ byte رقم i بيتعمله XOR مع key[i % 4]). فكها في مكانها واطبعها بـ print_str. المطلوب يطلع:
c2=10.0.0.5:8443 default rel section .data blob: db 0x70, 0x05, 0xFD, 0xEF, 0x23, 0x19, 0xF0, 0xF0, 0x23, 0x19, 0xF5, 0xE4, 0x2B, 0x03, 0xF4, 0xED, 0 BLOB_LEN equ 16 key: db 0x13, 0x37, 0xC0, 0xDE section .text global _start _start: ; decode blob in place: blob[i] ^= key[i % 4] lea rdi, [blob] call print_str call print_nl xor edi, edi call exit c2=10.0.0.5:8443 default rel section .data blob: db 0x70, 0x05, 0xFD, 0xEF, 0x23, 0x19, 0xF0, 0xF0, 0x23, 0x19, 0xF5, 0xE4, 0x2B, 0x03, 0xF4, 0xED, 0 BLOB_LEN equ 16 key: db 0x13, 0x37, 0xC0, 0xDE section .text global _start _start: lea rsi, [blob] lea r8, [key] xor ecx, ecx ; i = 0 .next: mov edx, ecx and edx, 3 ; i % 4 (4 is a power of two) mov al, [r8+rdx] ; key byte xor [rsi+rcx], al ; decode in place inc ecx cmp ecx, BLOB_LEN jb .next lea rdi, [blob] call print_str call print_nl xor edi, edi call exit rdi = الرقم، rsi = رقم الـ bit (0..63). رجّع في rax = 1 لو الـ bit ده = 1، و0 لو لأ. ممنوع bt — استخدم shift وand. (الـ shift بعدد متغير لازم يبقى في cl.) bit_set: xor eax, eax ret bit_set: mov rax, rdi mov ecx, esi shr rax, cl ; bring bit n down to bit 0 and eax, 1 ; keep only it ret رجّع في rax أصغر مضاعف لـ 16 أكبر من أو يساوي rdi (الـ alignment اللي بتشوفه قبل حجز ذاكرة على الـ stack). (x + 15) & ~15. align16: mov rax, rdi ret align16: lea rax, [rdi+15] and rax, -16 ; ~15 = 0xFFFF...FFF0 ret rdi = عنوان اسم API (string منتهية بـ 0). احسب: h = 0، ولكل حرف c: h = ror(h, 13) + c (32-bit). رجّع h في eax. التستات بتستخدم أسماء APIs حقيقية — والنتيجة لازم تطابق الجدول فوق. ror13_hash: xor eax, eax ; h = 0 .next: ; load one char, stop at 0, rotate, add ret ror13_hash: xor eax, eax ; h = 0 .next: movzx edx, byte [rdi] ; c = *name test edx, edx jz .done ; end of string ror eax, 13 add eax, edx ; h = ror(h,13) + c inc rdi jmp .next .done: ret الدالة دي بترجع 0 لو الـ key (في edi) صح. إيه الـ key؟ (فكّر بالعكس: كل عملية ليها عكس.) check_key: mov eax, edi rol eax, 7 xor eax, 0x1337 sub eax, 0x9A2B3C4D ; 0 only when the key is right ret عشان eax يبقى 0 لازم بعد الـ xor تبقى القيمة 0x9A2B3C4D. اعكس: XOR بنفس الـ 0x1337 تاني، وبعدين ROR بـ 7. 0x9A2B3C4D ^ 0x1337 = 0x9A2B2F7A، وبعدين ror(0x9A2B2F7A, 7) = 0xF534565E. الخطوات دي (اعكس كل عملية بالترتيب العكسي) هي بالظبط إزاي بتكتب keygen لأي crackme بسيط. shellcode بيدوّر على API بالـ hash 0x91AFCA54 (ROR13). اسم الـ API إيه؟ (هتلاقيه في جدول المرحلة — وبعدين اتأكد بالمعمل: الـ hash function تحت بتاخد اسم.) ror13_hash: xor eax, eax .next: movzx edx, byte [rdi] test edx, edx jz .done ror eax, 13 add eax, edx inc rdi jmp .next .done: ret shellcode بيحجز ذاكرة executable عشان يحط فيها الـ stage التانية… VirtualAlloc — الـ shellcode غالبًا هيحجز بيها ذاكرة RWX (flProtect = 0x40) وينسخ فيها payload. الـ hash بيتحسب case-sensitive، فلازم الاسم بالظبط.
