الكمبيوتر من جوه: الـ CPU والذاكرة ودورة التنفيذ

قبل أي instruction، لازم تبني في دماغك صورة صح للآلة: CPU بيقرا bytes من الذاكرة وينفّذها واحدة ورا التانية. كل حاجة في الكورس — الـ stack، الـ calls، الـ shellcode، الـ exploits — هي مجرد تطبيقات للصورة البسيطة دي.

الصورة الكبيرة CPU ↔ RAM

الكمبيوتر في جوهره حاجتين: الـ CPU اللي بيحسب، والذاكرة (RAM) اللي شايلة الكود والبيانات. الاتنين متوصلين بـ bus. الـ CPU مبيعرفش حاجة اسمها "متغير" أو "دالة" أو "string" — بيعرف عناوين وbytes بس.

⚡

Registers

خانات تخزين جوه الـ CPU نفسه، كل واحدة 64-bit. أسرع من الـ RAM بمئات المرات. الـ CPU بيعمل كل حساباته عليها تقريبًا.

🧮

ALU

الوحدة اللي بتحسب: جمع، طرح، ضرب، عمليات bits. بعد كل عملية بتسجّل "معلومات عن النتيجة" في RFLAGS (صفر؟ سالب؟ حصل overflow؟).

🧭

RIP

الـ Instruction Pointer: عنوان الـ instruction الجاية. أي تحكم في البرنامج (jump، call، ret، exploit) هو في الآخر تغيير قيمة RIP.

دورة التنفيذ: Fetch → Decode → Execute قلب كل حاجة

الحقيقة أعقد… بس مش مهمة لك دلوقتي

المعالجات الحديثة بتعمل pipelining وout-of-order execution وbranch prediction — بتنفذ عشرات الـ instructions بالتوازي. لكنها بتضمن إن النتيجة النهائية تبان كأن كل instruction اتنفذت لوحدها بالترتيب. الـ debugger والـ disassembler بيوروك النموذج المتسلسل ده، وهو اللي هتفكر بيه 99% من الوقت. (التفاصيل دي بتهم في ثغرات زي Spectre وفي الـ timing attacks.)

🎬 شوف الدورة دي متحركة على 4 instructions حقيقية: اضغط ▶ PLAY أو STEP، وتابع الـ bytes وهي طالعة من الـ RAM للـ CPU، والـ decoder بيفهمها، والـ registers بتتغير:

شوفها بعينك: أول معمل LAB

البرنامج ده 6 instructions. اضغط Step (F7) وراقب حاجتين: RIP بيزيد بمقدار طول كل instruction (بص على عمود الـ bytes)، والـ register اللي بيتغير بيولّع بلون مختلف. متقلقش من معنى الـ instructions دلوقتي — هنفصّلها كلها.

start: mov eax, 1 ; 5 bytes -> RIP += 5 add eax, 2 ; 3 bytes -> eax = 3 push rax ; 1 byte -> the stack grows pop rbx ; 1 byte -> rbx = 3 nop ; 1 byte -> does nothing ret ; return to the caller

الـ compilation بيرمي معلومات: أسماء المتغيرات، الأنواع، الـ comments، وأحيانًا شكل الـ loops نفسه. عشان كده الرجوع مش عملية عكسية مثالية — هو تحقيق. ده بالظبط شغلك كـ reverser. شوف نفس الدالة الصغيرة دي طلعت إيه من 3 compilers حقيقيين:

int add3(int a, int b, int c) { return a + b + c; }

وآخر خطوة: الـ assembler بيحوّل كل سطر لـ bytes. اضغط ⚙ Bytes على المثال ده عشان تشوف الـ machine code، و▶ تشغيل عشان يتنفذ فعلًا على Linux، و🔬 Debug عشان تمشي فيه خطوة بخطوة:

; The smallest useful Linux program: exit with code 42. ; Run it, then press "Bytes" to see the machine code. section .text global _start _start: mov eax, 60 ; syscall number 60 = exit mov edi, 42 ; first argument = exit code syscall ; ask the Linux kernel to do it

المخرجات فاضية، بس الـ exit code = 42. البرنامج ده كله 12 byte: B8 3C 00 00 00 BF 2A 00 00 00 0F 05. لاحظ إن 3C = 60 و2A = 42 بالـ hex، ومكتوبين بالمقلوب (الـ byte الصغير الأول) — ده الـ little-endian اللي هنفهمه في المرحلة الجاية.

x86: تاريخ بيفسر الغرابة ليه eax و ax و al؟

1978Intel 808616-bit. registers اسمها AX وBX… والذاكرة segments.
1985Intel 8038632-bit (IA-32): ظهرت EAX (Extended AX) والـ protected mode والـ paging.
2003AMD64 (Opteron)AMD مدّت x86 لـ 64-bit: RAX وR8–R15 والـ RIP-relative addressing.
2004Intel 64Intel تبنّت نفس الـ ISA (EM64T). الأسماء: x86-64 = AMD64 = Intel 64 = x64.
النهاردةx86-64كل instruction قديمة لسه شغالة (backward compatibility) — عشان كده الـ ISA ضخم ومليان استثناءات.

الـ x86 معمارية CISC (Complex Instruction Set): instructions كتير، طولها متغير، وبعضها بيعمل حاجات كبيرة (زي rep movsb اللي بتنسخ ذاكرة كاملة). العكس RISC (زي ARM): instructions قليلة، طولها ثابت (4 bytes)، والذاكرة بتتقرا/تتكتب بـ instructions مخصوصة بس. هنقارن الاتنين في مرحلة ARM64.

الـ register RIP بيحتوي على إيه؟ آخر قيمة اتحسبت في الـ ALU عنوان الـ instruction اللي هتتنفذ بعد كده عدد الـ instructions اللي اتنفذت عنوان قمة الـ stack RIP = Instruction Pointer. التحكم في RIP = التحكم في البرنامج كله، وده هدف أي exploit. الحرف IP = Instruction Pointer. قمة الـ stack دي RSP. mov eax, 1 عند العنوان 0x401000 طولها 5 bytes. بعد ما تتنفذ، RIP = ؟ 0x401001 0x401004 0x401005 0x401008 RIP بيزيد بطول الـ instruction بالظبط: 0x401000 + 5 = 0x401005. RIP بيعدّ bytes مش instructions. الطول 5. أقصى طول لـ instruction واحدة في x86-64؟ 4 bytes (زي ARM) 8 bytes 10 bytes 15 bytes من 1 لـ 15 byte. الطول المتغير ده (CISC) هو السبب إن الـ disassembler لازم يعرف هو بيبدأ منين بالظبط — وده اللي بيستغله الـ anti-disassembly. x86 طولها متغير، والحد الأقصى الرسمي رقم فردي. برنامج 32-bit شغّال على Windows 10 64-bit. الـ CPU شغّال في أنهي وضع؟ Long mode — compatibility sub-mode (عن طريق WoW64) Real mode Protected mode عادي من غير 64-bit Ring 0 الـ OS نفسه في long mode، والـ process الـ 32-bit بيشتغل في compatibility mode عن طريق طبقة WoW64. وده سبب إنك محتاج x32dbg للبرامج دي (وهتشوف تكنيك "Heaven's Gate" اللي بيقفز بين الوضعين). Windows 64-bit مش بيرجع لـ real/protected mode. فيه sub-mode جوه الـ long mode. برنامج عادي (user-mode) عايز يكتب في ملف. إزاي بيوصل للـ kernel؟ بيكتب مباشرة في ذاكرة الـ kernel بيستخدم hlt بـ syscall (مباشرة أو عن طريق API/libc بتعملها) مينفعش أصلًا الـ syscall هو الباب الرسمي من Ring 3 لـ Ring 0. على Windows عادة عن طريق kernel32 → ntdll → syscall. Ring 3 مسموحله يطلب بس، بـ instruction مخصوصة. أنهي أداة بتعمل bytes → Assembly بدقة (من غير "تخمين")؟ Decompiler Disassembler Compiler Linker الـ disassembler بيترجم الـ bytes لـ instructions (مع تحدي واحد: يعرف الكود بيبدأ فين). الـ decompiler هو اللي بيخمّن C. "dis-assemble" = عكس الـ assembler. حسب إحصائيات DLLs الـ Windows، أكتر instruction استخدامًا بفرق كبير؟ mov (~35%) call jmp xor ثلث الكود تقريبًا نقل بيانات. البرامج بتنقل أكتر ما بتحسب. فكّر: أغلب الكود بينقل قيم بين registers وذاكرة. ليه الـ malware يقدر يكتب bytes في الذاكرة وبعدين ينفّذها (زي الـ shellcode والـ unpackers)؟ عشان الـ CPU بيقرا الكود من الهارد ديسك مباشرة عشان الكود متخزن في الـ registers ده مستحيل على x86 عشان الكود والبيانات الاتنين bytes في نفس الذاكرة (von Neumann) — والـ CPU بينفّذ أي bytes RIP بيشاور عليها لو الصفحة executable بالظبط. الحماية الوحيدة هي صلاحيات الصفحات (NX/DEP) — والـ malware بيطلب صفحة RWX أو بيغيّر الصلاحيات بـ VirtualProtect/mprotect. ده من أهم الـ indicators اللي بتدور عليها. افتكر الـ diagram: الكود والبيانات فين؟ بالـ instructions اللي شفتها في المعمل (mov وadd وpush وpop)، خلّي rax = 7 وrbx = 7 في الآخر. الحد الأقصى 4 instructions — والـ ret بتتحسب منهم! (تلميح: push rax + pop rbx بينسخوا قيمة rax لـ rbx.) start: mov eax, 0 ret start: mov eax, 7 mov ebx, eax ret
