الحساب والـ Flags: إزاي الـ CPU "بيقرر"

الـ CPU مفيهوش if. فيه حاجة أبسط: كل عملية حسابية بتسيب flags (bits صغيرة في RFLAGS) بتوصف النتيجة: صفر؟ سالب؟ حصل carry؟ حصل overflow؟ والـ conditional jumps بتقرا الـ flags دي. لو فهمت المرحلة دي صح، أي if في أي binary هيبقى واضح قدامك.

الـ 6 Flags RFLAGS

0️⃣

ZF — Zero

1 لو النتيجة = 0. بعد cmp a, b: ZF=1 ⇐ a == b. أكتر flag هتشوفه (je/jne).

➖

SF — Sign

نسخة من أعلى bit في النتيجة. لو بتفسّر signed: SF=1 ⇐ النتيجة سالبة.

🚚

CF — Carry

overflow unsigned: الجمع طلّع رقم أكبر من الحجم، أو الطرح احتاج "يستلف" (a < b كـ unsigned). أساس jb/ja.

💥

OF — Overflow

overflow signed: النتيجة الحقيقية خرجت برا المدى، فإشارتها طلعت غلط (موجب + موجب = سالب). أساس jl/jg مع SF.

🎲

PF — Parity

1 لو عدد الـ bits اللي بواحد في أول byte من النتيجة زوجي. نادر في الكود العادي — بيظهر في مقارنات الـ floats (jp = NaN).

🔟

AF — Adjust

carry من bit 3 لـ bit 4. موجود للـ BCD القديم. تقريبًا مش هتحتاجه — المعمل بيعرضه للأمانة.

السر كله: الـ CPU مبيعرفش انت بتشتغل signed ولا unsigned، فبيحسب التفسيرين مع بعض: CF بيقولك "لو unsigned، حصل overflow؟"، وOF بيقولك "لو signed، حصل overflow؟". والـ instruction اللي بعدها (jump مثلًا) هي اللي بتختار أنهي واحد يهمها. افتكر دايرة الـ two's complement من المرحلة 02: عبور الخط البرتقالي = CF، والأحمر = OF.

💥
Divide Error (#DE)

القسمة بتعمل crash (exception) في حالتين: القسمة على صفر، أو لو الناتج مش بيكفي في الـ register (مثلًا INT_MIN / −1، أو rdx مش متصفّر). على Linux = SIGFPE، وعلى Windows = EXCEPTION_INT_DIVIDE_BY_ZERO (0xC0000094). فيه malware بيستخدم القسمة على صفر عمدًا عشان يطلّع exception يمشي بيها الـ control flow لـ handler بتاعه (anti-debugging/obfuscation).

الـ Compiler بيكره div real output

div بطيئة جدًا (عشرات الـ cycles)، فلما المقسوم عليه ثابت، الـ compilers بيستبدلوها بضرب في "رقم سحري" + shift. والقسمة على 2 للـ signed محتاجة تصحيح عشان C بتقرّب ناحية الصفر. شوف الـ output الحقيقي:

int avg(int a, int b) { return (a + b) / 2; } unsigned int div10(unsigned int x) { return x / 10; } int mod8(int x) { return x % 8; } int mul12(int x) { return x * 12; } long divide(long a, long b) { return a / b; }
🔬
هتشوف الـ magic numbers دي كتير

القاعدة: mov eax, M + mul/imul + shr edx, k = قسمة على 2^(32+k) / M تقريبًا. أشهرهم: 0xCCCCCCCD (÷10)، 0xAAAAAAAB (÷3)، 0x55555556 (÷3 signed)، 0x66666667 (÷5/÷10 signed)، 0x92492493 (÷7 signed). IDA/Ghidra غالبًا بيحلّوها في الـ decompiler، بس في الـ disassembly لازم تعرفها. هنعمل جدول كامل في مرحلة أنماط الـ compiler.

حساب أكبر من 64-bit: adc multi-precision

عشان تجمع رقمين 128-bit (كل واحد في register-ين)، اجمع النص السفلي بـ add، والعالي بـ adc اللي بتزوّد الـ carry. ده نفس الجمع اللي بتعمله بإيدك في المدرسة (الحمل للخانة اللي بعدها). مكتبات التشفير (RSA، bignums) مليانة adc وsbb وmul — لو شفت loop فيها adc كتير، غالبًا crypto.

; 128-bit addition: (2^64 - 1) + 1 = 2^64 -> high = 1, low = 0 section .text global _start _start: mov rax, -1 ; a.low = 0xFFFFFFFFFFFFFFFF xor edx, edx ; a.high = 0 add rax, 1 ; low = 0, CF = 1 (carry out) adc rdx, 0 ; high = 0 + 0 + CF = 1 mov rdi, rdx call print_hex ; 0x1 call print_nl mov rdi, rax call print_hex ; 0x0 call print_nl xor edi, edi call exit

(xor = قلب الـ bits لو الـ mask كله واحد — هنتعمق فيها المرحلة الجاية.) my_abs: mov eax, edi ret my_abs: mov eax, edi cdq ; edx = 0 if x >= 0, else 0xFFFFFFFF xor eax, edx ; flip all bits when negative sub eax, edx ; ... and add 1 (subtracting -1) ret بعد الكود ده، إيه قيمة edx؟ mulhi: mov eax, 0x10000 mov ecx, 0x10000 mul ecx ; edx:eax = eax * ecx ret 0x10000 × 0x10000 = 0x100000000 — عدّ الأصفار: ده محتاج 33 bit. 2¹⁶ × 2¹⁶ = 2³² = 0x1_00000000. الـ 32 bit السفلى (eax) = 0، والعليا (edx) = 1. وCF=OF=1 لأن النتيجة مكفتش في eax. الدالة دي بتقسم edi (unsigned) على رقم ثابت. على كام؟ magic: mov eax, edi mov edx, 0xAAAAAAAB mul edx shr edx, 1 mov eax, edx ret 0xAAAAAAAB ≈ 2³³/3. أو جرّب في المعمل: افتح 🔬 Debug وغيّر edi.
