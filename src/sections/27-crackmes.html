سلسلة Crackmes: من الـ strcmp للـ VM

كل crackme دالة check(rdi = key) بترجع 1 لو الـ key صح. اقرا الكود، افهم الشرط، واكتب key يعدّي. في الـ crackmes اللي عليها 🧪 keygen: فيه مفاتيح كتير صح — الصفحة بتشغّل الكود بتاعك في المعمل بالـ key اللي كتبته، فأي key سليم هيتقبل. افتح 🔬 Debug على أي واحدة وجرّب بـ rdi=&"…".

🧪
طريقة الشغل

(1) اقرا الكود من غير تشغيل وحدد: الـ input بيتقري إزاي؟ الشرط النهائي إيه؟ (2) اكتب اللي فهمته كـ C في ورقة. (3) استنتج الـ key (أو اكتب keygen). (4) اتأكد في المعمل: 🔬 Debug ← Setup ← rdi=&"KEY" ← Run ← rax = 1؟

🔑 الـ Crackmes

الـ key كله بيتقارن في instruction واحدة. check: ; rdi = key mov rax, 0x0033737233763352 cmp [rdi], rax ; 8 bytes at once (incl. the terminating NUL) jne .bad mov eax, 1 ret .bad: xor eax, eax ret little-endian: أقل byte = أول حرف. 0x52 = 'R'. الـ bytes في الذاكرة: 52 33 76 33 72 73 33 00 = R3v3rs3 + NUL. الـ NUL جزء من المقارنة، فـ R3v3rs3! مش هتعدّي. كل حرف بيتعمله XOR ويتقارن بجدول في .data. section .data enc: db 0x4F, 0x07, 0x45, 0x68, 0x5C, 0x04, 0x4E, 0x16 section .text check: ; rdi = key xor ecx, ecx .loop: movzx eax, byte [rdi+rcx] xor al, 0x37 cmp al, [enc+rcx] jne .bad inc ecx cmp ecx, 8 jne .loop cmp byte [rdi+8], 0 ; exactly 8 characters jne .bad mov eax, 1 ret .bad: xor eax, eax ret key[i] = enc[i] ^ 0x37. 0x4F^0x37 = 'x'، 0x07^0x37 = '0'… ← x0r_k3y!. الـ XOR بيرجع لأصله لو عملته مرتين — نفس كل الـ string decoders. فيه آلاف المفاتيح الصح. لاقي واحد (أي واحد). check: ; print(f"{name}-{(s ^ 0xBEEF) & 0xFFFF:04X}") — مثلًا ZZZZ-BD6B. ده نفس شكل الـ license checks في البرامج القديمة. الـ check مكتوب بـ bytecode لـ VM صغير (زي VMProtect بس لعبة). افهم الـ opcodes، فك البرنامج، وطلّع الـ key. section .data prog: ; [opcode, operand] pairs db 0x01, 0x00, 0x02, 0x13, 0x04, 0x45 db 0x01, 0x01, 0x03, 0x28, 0x04, 0x75 db 0x01, 0x02, 0x02, 0x35, 0x04, 0x01 db 0x01, 0x03, 0x03, 0x36, 0x04, 0x9B db 0x01, 0x04, 0x02, 0x57, 0x04, 0x21 db 0x01, 0x05, 0x03, 0x44, 0x04, 0xA9 db 0x01, 0x06, 0x02, 0x79, 0x04, 0x0B db 0x05, 0x07, 0xFF, 0x00 section .text check: ; rdi = key lea rsi, [rel prog] ; vm instruction pointer xor eax, eax ; vm accumulator .fetch: movzx ecx, byte [rsi] ; opcode movzx edx, byte [rsi+1] ; operand add rsi, 2 cmp ecx, 1 je .load cmp ecx, 2 je .xor cmp ecx, 3 je .add cmp ecx, 4 je .cmp cmp ecx, 5 je .len cmp ecx, 0xFF je .win jmp .bad .load: movzx eax, byte [rdi+rdx] ; acc = key[operand] jmp .fetch .xor: xor eax, edx jmp .fetch .add: add eax, edx and eax, 0xFF jmp .fetch .cmp: cmp eax, edx jne .bad jmp .fetch .len: cmp byte [rdi+rdx], 0 ; key[operand] must be the end jne .bad jmp .fetch .win: mov eax, 1 ret .bad: xor eax, eax ret الـ opcodes: 1 = LOAD key[i]، 2 = XOR، 3 = ADD (8-bit)، 4 = CMP، 5 = END-OF-STRING، 0xFF = WIN. كل حرف: LOAD i ← (XOR k أو ADD k) ← CMP t. اعكس: لو XOR: c = t ^ k، لو ADD: c = (t − k) mod 256. (0x45^0x13)='V'، (0x75−0x28)='M'، (0x01^0x35)='4'، (0x9B−0x36)='e'، (0x21^0x57)='v'، (0xA9−0x44)='e'، (0x0B^0x79)='r' ← VM4ever. ده جوهر تحليل الـ VM protectors: (1) لاقي الـ dispatcher (fetch + switch)، (2) افهم كل handler، (3) اكتب disassembler للـ bytecode، (4) حلّل البرنامج المفكوك.
