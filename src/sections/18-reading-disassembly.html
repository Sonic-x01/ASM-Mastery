منهجية قراية الـ Disassembly

sample فيه 3000 دالة. لو قريتهم بالترتيب هتقعد شهر. الـ analyst المحترف عنده منهجية: يعرف يبدأ منين، يدوّر على إيه، يتجاهل إيه، وإزاي يحوّل الـ asm لفهم مكتوب (أسماء، types، تعليقات) خطوة خطوة. المرحلة دي هي الـ workflow ده — وهتطبقه على دالة حقيقية.

الـ Workflow 7 خطوات

1

Triage (من غير ما تفتح disassembler)

نوع الملف، 32/64، الـ compiler/packer (Detect It Easy)، الـ hashes، الـ sections والـ entropy (entropy عالية ≈ مضغوط/متشفر)، الـ imports، والـ strings (وFLOSS للـ strings المتشفرة). capa بيقولك القدرات (injection، persistence…) ومكانها.

2

لاقي نقطة البداية الحقيقية

الـ entry point مش main. وصّل لـ main/WinMain/DllMain (المشهد تحت)، وافتكر الكود اللي بيشتغل قبل main: constructors وTLS callbacks.

3

Bottom-up من الحاجات المثيرة

بدل ما تقرا من فوق: خد import مهم (InternetOpenUrlA، CreateRemoteThread، CryptDecrypt) أو string غريبة ← xrefs (X في IDA) ← الدالة اللي بتستخدمها ← اطلع لفوق للـ callers.

4

Top-down من main

اقرا main على مستوى الـ calls بس: كل call ← خمّن وظيفتها من الـ args والـ APIs اللي جواها، وسمّيها (maybe_persist). مش لازم تفهم كل دالة 100% من أول مرة.

5

Annotate بلا رحمة

كل حاجة فهمتها اكتبها في الـ database: rename (N)، تعليقات (;)، types وstructs (أهم حاجة — الـ struct الصح بيخلّي الـ decompiler يطلع كود نضيف)، enums للثوابت.

6

اتأكد dynamically

الـ static تخمين لحد ما يتثبت: breakpoint في x64dbg/gdb، شوف القيم الحقيقية (المفتاح، الـ string بعد الفك، الـ args). في VM معزولة من غير network حقيقية.

7

اكتب النتيجة

الـ IOCs (domains، IPs، mutex، registry keys، hashes)، الـ capabilities، ووصف الخوارزميات (زي فك الـ config) — وأحسن حاجة: config extractor أو YARA rule يشتغلوا على samples تانية من نفس العيلة.

🪟

MSVC console: main

mainCRTStartup ← __scrt_common_main_seh. دوّر جوه على call قبلها __p___argv/__p___argc وبعدها مباشرة call exit (أو _cexit): mov ecx, [argc] / mov rdx, [argv] / mov r8, envp / call main ثم mov ecx, eax / call exit.

🖼️

MSVC GUI: WinMain

نفس الطريق، والـ call بتاخد 4 args: rcx = __ImageBase (غالبًا 0x140000000)، edx = 0، r8 = command line، r9d = show mode. اللي يشاور على الـ ImageBase كأول arg = WinMain.

🧩

DLL: DllMain

_DllMainCRTStartup ← dllmain_dispatch ← DllMain(hinst, reason, reserved). الـ edx = السبب: 1 PROCESS_ATTACH (هنا الـ payload عادة)، 0 DETACH، 2/3 THREAD. لكن الـ malware DLL كتير بيشتغل من export (rundll32 بيناديه) — بص على جدول الـ exports.

⏱️

قبل main

Linux: .init_array (constructors). Windows: TLS callbacks (بتشتغل قبل الـ entry point نفسه — مكان مفضّل للـ anti-debug) والـ C++ static initializers (_initterm). IDA بيعرض الـ TLS callbacks في قائمة الـ entry points (Ctrl+E).

ونفس الدالة من MSVC: الـ loop اختفت خالص. MSVC حسب الـ rolling key وقت الـ compile وفرد الـ 40 byte، كل واحد بمفتاحه: xor al, 60 ثم 165 ثم 132… نفس الخوارزمية، شكل مختلف تمامًا — لو مش واخد بالك هتفتكره XOR بمفتاح طويل عشوائي:

#include struct config { char host[32]; unsigned short port; unsigned int sleep_ms; }; extern const unsigned char g_blob[40]; int load_config(struct config *out) { unsigned char buf[40]; unsigned char k = 0x3C; for (int i = 0; i < 40; i++) { buf[i] = g_blob[i] ^ k; k = k * 7 + 1; /* rolling key */ } if (buf[0] != 'C' || buf[1] != 'F') /* magic "CF" */ return -1; memcpy(out->host, buf + 2, 32); out->port = buf[34] | (buf[35] << 8); memcpy(&out->sleep_ms, buf + 36, 4); return 0; }

الـ Decompiler: صاحبك اللي بيكدب أحيانًا

🎭

Types غلط

من غير struct هيطلع *(_WORD *)(a1 + 32). عرّف الـ struct وطبّقه ← out->port. والـ signed/unsigned بيتخمن من الـ jcc والـ shifts.

🔢

عدد الـ arguments

لو دالة بتقرا register مبيتحطش (أو الـ convention غلط: __thiscall، __fastcall، syscall stub) الـ decompiler هيزوّد/ينقّص args. صحّح الـ prototype (Y في IDA).

🌀

Control flow مكسور

jump tables مش متحللة، دوال noreturn مش متعرفة (الكود اللي بعد exit بيتلزق في الدالة)، opaque predicates، وكود متداخل. لو الـ decompiler قال حاجة غريبة ← ارجع للـ asm.

🧹

بيخفي التفاصيل المهمة

الـ idioms اللي في المرحلة 17 بتتحوّل صح غالبًا، لكن حاجات زي rdtsc، cpuid، int 2Dh، syscall مباشر، أو تلاعب بالـ stack بتطلع __asm أو تختفي. الـ anti-analysis بيعيش في التفاصيل دي.
