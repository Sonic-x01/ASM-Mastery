ليه Assembly؟ وإزاي تذاكر الكورس ده صح

في تحليل الـ Malware مفيش source code. اللي في إيدك ملف bytes، والـ disassembler بيحوّله لـ Assembly. كل حاجة تانية — الـ decompiler، الـ signatures، الـ sandboxes — أدوات مساعدة بتغلط وبتتخدع. الـ Assembly هي الحقيقة الوحيدة عن اللي البرنامج بيعمله. الكورس ده هيخليك تقراها بطلاقة، وتكتبها، وتفهم الـ CPU اللي بينفذها.

🔬

الـ decompiler بيكدب أحيانًا

Ghidra وIDA بيطلعولك pseudo-C حلو… لحد ما الـ malware يستخدم obfuscation أو anti-disassembly أو calling convention غريبة. ساعتها الـ pseudo-C بيبقى غلط، واللي بيفهم الـ Assembly بس هو اللي بيكمّل.

🧬

Shellcode وPackers مفيهمش C

الـ shellcode والـ unpacking stubs والـ decoders بتتكتب Assembly مباشرة. مفيش decompiler هيساعدك فيها كتير — لازم تمشي فيها instruction ورا instruction.

🐞

الـ Debugger بيتكلم Assembly

x64dbg وWinDbg وgdb بيوروك registers وflags وstack وinstructions. عشان تتحكم في الـ sample وتعدّي الـ anti-debugging وتطلّع الـ config، لازم تفهم كل سطر.

⚡

Patching وExploitation

تغيير byte واحد (74 → 75) ممكن يقلب شرط كامل. فهم الـ encoding والـ stack هو أساس الـ patching وفهم الثغرات والـ exploits اللي الـ malware بيستغلها.

رحلتك في الكورس من الـ bits لحد الـ crackmes

01

الأساسيات: الآلة من جوه (01 → 05)

الـ CPU والذاكرة ودورة التنفيذ، الأنظمة العددية والـ two's complement والـ endianness، الـ registers، الذاكرة والـ addressing modes، وأدواتك: NASM وgdb وx64dbg وأول برنامج.

02

الـ Instructions بالتفصيل (06 → 12)

نقل البيانات، الحساب والـ flags (أهم درس في الكورس)، الـ bits والـ shifts، التحكم في التدفق، الـ stack والدوال، الـ calling conventions (Linux وWindows و32-bit)، والـ string instructions.

03

البرمجة الحقيقية (13 → 16)

برامج Linux كاملة بالـ syscalls، الـ arrays والـ structs، Assembly مع C والـ macros وبرامج Windows x64 بتنادي الـ API، والـ floating point والـ SIMD زي ما بتظهر في الكود الحقيقي.

04

الهندسة العكسية (17 → 26)

أنماط الـ compilers (gcc وMSVC)، منهجية قراية الـ disassembly، الـ machine code والـ patching، PE/ELF، الـ x86 32-bit، الـ PEB والـ API hashing، الـ shellcode، الـ anti-debugging والـ obfuscation، C++ في الـ binary، وARM64.

05

التطبيق (27 → النهاية)

سلسلة crackmes بتتحل جوه الصفحة، مشاريع حقيقية (string decoders، API hash resolver، PE walker، تحليل shellcode…)، وCheat Sheet ومصادر.

إزاي تستخدم الصفحة الأدوات اللي معاك

▶

تشغيل حقيقي

زرار تشغيل بيبعت الكود لـ Compiler Explorer: بيتعمله assemble بـ NASM 3.01 ويتربط بـ ld ويتنفذ على Linux x86-64 حقيقي.

🔬

Debug خطوة بخطوة

زرار Debug بيفتح الكود في المعمل: debugger كامل جوه الصفحة بيشتغل من غير إنترنت. نفس اختصارات x64dbg: F7 وF8 وF9.

⚙

الـ Machine Code

زرار Bytes بيوريك كل instruction اتحولت لأنهي bytes — زي عمود الـ bytes في x64dbg وIDA بالظبط.

⧉

Graph View

أي listing عليه زرار Graph بيرسم الـ control-flow graph زي IDA: أخضر = الشرط اتحقق، أحمر = متحققش.

🏭

Compilers حقيقيين

كل مقارنة "C → Assembly" في الكورس طالعة من gcc وMSVC وclang فعليًا وقت بناء الصفحة — مش مكتوبة بالإيد.

🎯

5 أنواع تمارين

أسئلة، تحديات بتتصحح على CPU حقيقي، تحديات Lab بتتصحح في الـ emulator، مهام RE (لاقي الـ key)، ومشاريع.

🧪
المعمل متحقق منه ضد CPU حقيقي

الـ emulator اللي جوه الصفحة اتكتب مخصوص للكورس، واتجرب على أكتر من 23,000 instruction عشوائية اتنفذت على معالج حقيقي — نفس الـ registers ونفس الـ flags بالظبط. والـ bytes اللي بيطلعها متطابقة مع NASM في 3,237 حالة. وكل مثال NASM في الصفحة بيتنفذ على Linux حقيقي ونتيجته لازم تطابق نتيجة المعمل وإلا الصفحة مبتتبنيش.

🛡️
قاعدة الأمان

كل الأكواد هنا تعليمية وآمنة. لما تبدأ تحلل samples حقيقية: VM معزولة دايمًا (FLARE-VM للـ Windows وREMnux للـ Linux)، من غير shared folders، شبكة host-only، وsnapshot نضيف ترجعله بعد كل تحليل. متشغلش sample على جهازك الأساسي أبدًا.

💡
إزاي تذاكر

(1) اقرا الشرح. (2) افتح المعمل وامشي بـ F7 وتوقّع قيمة كل register قبل ما تضغط. (3) حل التمارين من غير ما تبص على الحل. (4) بعد كل جزء: خد أي برنامج كتبته بـ C، اعمله compile، وافتحه في x64dbg أو Ghidra. التوقّع قبل التنفيذ هو أسرع طريق لبناء "CPU في دماغك".

✏️ قبل ما تبدأ

إنت بتحلل sample جديد ومعاك Ghidra. الـ decompiler طلّع pseudo-C شكله غريب ومش منطقي في function مهمة. أحسن خطوة؟ تثق في الـ pseudo-C وتكمّل تشغّل الـ sample على جهازك عشان تشوف بيعمل إيه ترجع للـ disassembly نفسه وتقرا الـ instructions، وتأكد بالـ debugger جوه VM تعمل skip للـ function الـ Assembly هي المصدر الحقيقي. الـ decompiler مجرد تفسير ليها وممكن يتلخبط من الـ obfuscation أو الـ anti-disassembly. والتشغيل دايمًا جوه VM معزولة. فكّر: إيه المصدر اللي مبيكدبش؟ وفين المكان الآمن للتشغيل؟ المعمل جوه الصفحة بيستخدم نفس اختصارات x64dbg. F8 بيعمل إيه؟ Step Into: بيدخل جوه أي call Step Over: بينفذ الـ call كله ويقف على اللي بعده Run لحد الآخر بيرجع خطوة لورا F7 = Step Into، F8 = Step Over، F9 = Run. نفس اللي هتستخدمه في x64dbg بالظبط. Into = تدخل جوه الدالة، Over = تعدّيها.
