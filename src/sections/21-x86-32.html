x86 32-bit: اللي لسه هتقابله كتير

جزء كبير من الـ malware لسه 32-bit: droppers قديمة وجديدة، shellcode، عائلات مشهورة، وأدوات بتتعمل build لـ x86 عشان تشتغل في كل حتة (WoW64). الفرق الأكبر مش الـ registers — هو إن الـ arguments على الـ stack، وده بيغيّر شكل كل function.

عدّ الـ args بسرعة

cdecl: add esp, 10h بعد الـ call ← 4 args. stdcall: retn 0Ch في آخر الدالة ← 3 args. fastcall: أول اتنين في ecx، edx. thiscall (C++ MSVC): this في ecx.

🏷️

Name decoration

MSVC: _func (cdecl)، _func@12 (stdcall)، @func@8 (fastcall). الاسم نفسه بيقولك الـ convention وحجم الـ args — حتى في الـ imports: __imp__InternetConnectA@32 = 8 args.

GetPC: «أنا فين في الذاكرة؟»

مفيش RIP-relative في الـ 32-bit. الكود اللي ممكن يتحمّل في أي عنوان (shellcode، PIC) لازم يعرف عنوانه بنفسه — والحيلة إن call بتعمل push لعنوان الرجوع:

; shellcode-style GetPC (32-bit) call next ; E8 00 00 00 00 -> pushes the address of 'next' next: pop ebx ; ebx = runtime address of 'next' lea esi, [ebx + (data - next)] ; data relative to ebx, wherever we are loaded ; gcc -m32 -fPIC does the same thing with a helper: call __x86.get_pc_thunk.bx add ebx, OFFSET _GLOBAL_OFFSET_TABLE_ ; ebx = GOT base __x86.get_pc_thunk.bx: mov ebx, [esp] ; read the return address ret
🎯
توقيعات GetPC في الـ shellcode

E8 00 00 00 00 + pop reg (call $+5)، أو call لورا (E8 FF FF FF FF + byte… «call into the middle»)، أو x87 fldz + fnstenv [esp-0Ch] + pop (shikata_ga_nai). أي واحدة منهم في buffer = بداية shellcode غالبًا. في x64 مفيش داعي ليهم: lea rax, [rip].

SEH: الـ exceptions على الـ stack

; register a Structured Exception Handler (32-bit Windows) push offset handler ; EXCEPTION_REGISTRATION.Handler push dword ptr fs:[0] ; .Next = previous record mov dword ptr fs:[0], esp ; TEB.ExceptionList = our record xor eax, eax mov dword ptr [eax], 1 ; deliberate access violation -> handler runs ; ... code here only looks dead

الـ malware 32-bit بيستخدم SEH كـ control flow مخفي: يعمل exception بقصد، والـ handler يغيّر Context->Eip ويكمّل في مكان تاني. الـ disassembler شايف crash، والـ debugger بيقف على الـ exception الأول (first-chance) — فلازم تعدّيها (Shift+F9 في x64dbg) أو تحط breakpoint على الـ handler. لو شفت fs:[0] بيتكتب ← دوّر على الـ handler.

WoW64

process 32-bit على Windows 64: بيشوف C:\Windows\SysWOW64 بدل System32، وكل syscall بيعدّي على طبقة تحويل لـ 64-bit. أدوات الـ 32-bit (x32dbg) بتشوف الجزء الـ 32 بس.

Heaven's Gate

push 33h ثم call $+5 ثم add [esp], 5 ثم retf: far return لـ segment 0x33 = الـ CPU يتحوّل لـ 64-bit mode جوه process 32-bit! الـ malware بيستخدمه ينفذ كود 64-bit يتخطى hooks الـ 32-bit والـ debugger الـ 32-bit. لو شفت retf/jmp far مع 0x33 ← ده هو.

في دالة 32-bit عادية (بـ ebp frame)، [ebp+0Ch] هو: أول argument تاني argument عنوان الرجوع متغير محلي [ebp] = ebp القديم، [ebp+4] = return، [ebp+8] = arg1، [ebp+0Ch] = arg2، [ebp+10h] = arg3. ابدأ من [ebp+8] = الأول. بعد call sub_401200 مفيش add esp، والدالة نفسها بتنتهي بـ retn 8. الدالة: cdecl بـ 8 args مبتاخدش args fastcall بـ 8 args stdcall بـ 2 args (8 bytes) ret N = الدالة بتشيل N bytes = N/4 args (لو كلهم 4 bytes). N بالـ bytes مش بعدد الـ args. في كود MSVC 32-bit متحسن: push esi ثم mov eax, [esp+8]. الـ [esp+8] هنا: أول argument — لأن الـ push زوّد 4 على المسافة المعتادة [esp+4] تاني argument esi المحفوظ عنوان الرجوع عند الدخول: [esp] = return، [esp+4] = arg1. بعد push واحد كل حاجة اتزحزحت 4. IDA بيحسبها لك ويكتب [esp+4+arg_0]. احسب الـ push. sample 32-bit فيه mov eax, fs:[30h]. ده بيجيب: الـ TEB الـ stack الـ PEB — بداية الـ anti-debug (BeingDebugged) أو البحث عن الـ DLLs الـ SEH chain fs:[30h] (32) = gs:[60h] (64) = PEB. وfs:[0] = SEH chain، وfs:[18h] = الـ TEB نفسه. المرحلة الجاية بالتفصيل. كود 32-bit: push esi push 0 push offset aUpdateexe ; "update.exe" push eax call sub_402310 add esp, 10h add esp بعد الـ call = cdecl. 0x10 = 16 byte = 4 args (الأربع pushes اللي قبل الـ call). وأول arg = آخر push = eax. في الـ imports: __imp__InternetConnectA@32. الدالة بتاخد كام argument؟ @32 = bytes. 32 / 4 = 8 args (hInternet، server، port، user، password، service، flags، context) — وstdcall: الدالة بتنضف بـ ret 20h. عند 0x401000: E8 00 00 00 00 ثم 58 (pop eax). قيمة eax بعد الـ pop؟ call بتعمل push لعنوان الـ instruction اللي بعدها، والـ rel = 0 يعني القفزة ليها هي نفسها. عنوان الرجوع = 0x401005 (= عنوان الـ pop نفسه). ومن هنا الـ shellcode بيحسب مكان بياناته. MSVC حوّل caller() لـ mov eax, 524512011 فقط. اتأكد بنفسك: الـ hash = h = 7، ولكل حرف في "beacon": h = h*31 + c (32-bit). اكتب الناتج عشري. اكتبها بسكربت صغير (Python) — أو صدّق الـ compiler 😉. 0x1F436B0B = 524512011. الدرس: الـ constant folding ممكن يخفي الخوارزمية كلها ويسيب النتيجة بس. لو لقيت ثابت غريب بيتقارن بـ hash — جرّب تحسب hashes لـ strings متوقعة (أسماء APIs، processes) لحد ما يطابق (مرحلة 22).
