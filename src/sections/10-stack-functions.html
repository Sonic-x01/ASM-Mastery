الـ Stack والدوال: call وret والـ frames

الـ stack هو اللي بيخلي الدوال ممكنة: بيفتكر "أرجع فين"، وبيشيل المتغيرات المحلية، والـ registers المحفوظة. وفي نفس الوقت هو أشهر هدف للهجوم: لو قدرت تكتب على عنوان الرجوع، بقيت بتتحكم في RIP. المرحلة دي أساس كل الـ debugging وكل الـ exploitation.

الـ Stack: منطقة بتكبر لتحت LIFO

⬇️

بيكبر ناحية العناوين الأصغر

RSP بيشاور على آخر قيمة اتحطت (قمة الـ stack). push بتنقّص RSP بـ 8 وتكتب، وpop بتقرا وتزوّد RSP بـ 8. "فوق" الـ stack = عناوين أصغر — عكس الحدس، فارسمه دايمًا بالعناوين الكبيرة تحت.

♻️

مفيش مسح

الـ pop مبتمسحش القيمة — بس RSP بيتحرك. القيمة لسه في الذاكرة "تحت RSP" وهتتكتب فوقها في أول push. عشان كده ممكن تلاقي بيانات حساسة (keys، passwords) لسه موجودة في ذاكرة الـ stack بعد ما الدالة خلصت — كنز في الـ memory forensics.

الـ Stack Frame prologue · locals · epilogue

كل دالة (في الكود غير المحسّن على الأقل) بتبني frame بنفس الشكل. لو حفظت الصورة دي، هتقرا أي [rbp−x] و[rbp+x] فورًا:

frame لدالة على x64 (rbp-based) — العناوين الكبيرة تحت
rsp →…مساحة لـ arguments الدوال اللي هتتنادى (outgoing)
rbp − 16local 2متغيرات محلية / buffers
rbp − 8local 1 / canaryالـ canary بيتحط هنا بين الـ buffers وrbp
rbpsaved rbprbp بتاع الـ caller (push rbp)
rbp + 8return addressاللي الـ call حطته — هدف الـ overflow
rbp + 16…frame الـ caller (أو args على الـ stack في 32-bit / الـ shadow space في Win64)

وده الكود الحقيقي من gcc لنفس النوع من الدوال — لاحظ الحاجات اللي الـ compiler عملها فعلًا:

int leaf(int a) { int x = a * 2; int y = x + 3; return x + y; } long fact(long n) { if (n <= 1) return 1; return n * fact(n - 1); }
🏷️

Frame Pointer Omission

في -O2 (وMSVC دايمًا تقريبًا) مفيش rbp frame: الـ locals بتتوصل بـ [rsp+x]، وrbp بيبقى register عادي. ده بيصعّب الـ stack walking — وعشان كده Windows x64 بيحط جداول unwind (.pdata) لكل دالة.

📏

قاعدة الـ 16

الـ ABI على النظامين: قبل أي call لازم rsp يبقى مضاعف 16. فعند دخول أي دالة rsp ≡ 8 (mod 16) (بسبب عنوان الرجوع). عشان كده هتلاقي sub rsp, 28h / 38h / 48h — كلها ≡ 8.

🔁

Recursion

كل نداء = frame جديد فوق اللي قبله. الـ recursion العميقة جدًا (أو اللانهائية) بتخلص الـ stack (1 MB افتراضيًا على Windows، 8 MB على Linux) ← stack overflow (0xC00000FD) — ده غير الـ buffer overflow.

fact: ; rax = fact(rdi) cmp rdi, 1 jle .base push rdi ; save n (we need it after the call) dec rdi call fact ; rax = fact(n - 1) pop rdi ; restore n imul rax, rdi ; rax = n * fact(n - 1) ret .base: mov eax, 1 ret
👀
شوف الـ stack بيتملي وبيفضى

اضغط F7 كتير وراقب: كل call fact بتحط عنوان رجوع (برتقالي) + push rdi بتحط n. لحد ما n يوصل 1، هتلاقي 4 frames فوق بعض. وبعدين كل ret بتفك واحدة. جرّب ⤺ Back ترجع لورا وتعيد.

الـ RE والـ exploits

لما تحلل exploit (أو malware بيستغل ثغرة)، أول سؤال: الـ offset من بداية الـ buffer لعنوان الرجوع كام؟ لو الـ buffer عند rbp-0x30، يبقى عنوان الرجوع عند 0x30 + 8 = 0x38 byte من أوله (الـ 8 بتوع الـ saved rbp). الـ exploits الحديثة مبتقدرش تنفذ كود من الـ stack (NX)، فبتستخدم ROP: سلسلة عناوين لقطع كود موجودة أصلًا بتخلص بـ ret.
