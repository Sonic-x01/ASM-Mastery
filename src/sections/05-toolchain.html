الأدوات وأول برنامج: NASM وgdb وx64dbg

هنا هتكتب أول برامج حقيقية بالكامل: من ملف .asm لـ ELF شغّال، وتفتحه في debugger. وهتتعلم "تشريح" أي برنامج NASM، والفرق بين صيغ الـ Assembly المختلفة اللي هتشوفها في الأدوات.

تشريح برنامج NASM anatomy

; hello.asm — Linux x86-64, no libc: talk to the kernel directly default rel ; RIP-relative addressing by default section .data ; initialised, writable data msg: db "Hello from Assembly!", 10 ; the bytes of the text + '\n' len equ $ - msg ; assemble-time constant: length = 21 section .text ; the code global _start ; export the entry point for the linker _start: mov eax, 1 ; syscall number: 1 = write mov edi, 1 ; fd 1 = stdout lea rsi, [msg] ; pointer to the buffer mov edx, len ; number of bytes syscall ; write(1, msg, len) mov eax, 60 ; syscall number: 60 = exit xor edi, edi ; status 0 syscall ; exit(0)

ليه Linux للأمثلة رغم إن أغلب الـ malware Windows؟

برامج Linux بالـ syscalls المباشرة أبسط بكتير (مفيش imports ولا DLLs ولا PE headers)، فبتركز على الـ Assembly نفسها. الـ instructions والـ registers والـ stack واحدة على النظامين — الفرق في الـ calling convention والـ APIs، وهنغطي Windows بالتفصيل (برامج NASM بتنادي WinAPI، PE، PEB، x86 32-bit). وعندك WSL على جهازك — استخدمه.

gdb: الـ debugger على Linux cheat sheet

$ gdb -q ./hello (gdb) set disassembly-flavor intel # put this line in ~/.gdbinit (gdb) starti # stop at the very first instruction (gdb) layout asm # TUI: code window (layout regs = + registers) (gdb) si # step one instruction (into calls) (gdb) ni # step one instruction (over calls) (gdb) info registers rax rsi rip # read registers (p/x $rax also works) (gdb) x/s $rsi # examine memory as a string (gdb) x/16xb $rsp # 16 bytes in hex at the stack top (gdb) x/4xg $rsp # 4 qwords (giant words) (gdb) b *0x401016 # breakpoint on an address (gdb) c # continue until the next breakpoint (gdb) display/i $pc # always show the next instruction

الـ gdb الخام قاسي شوية — ثبّت GEF أو pwndbg: بيعرضوا الـ registers والـ stack والـ code مع كل خطوة (زي المعمل بتاعنا). x/FMT: الحرف الأول العدد، وبعده الشكل (x hex، d decimal، s string، i instruction) والحجم (b byte، h 2، w 4، g 8).

الحزمة فيها الاتنين: x64dbg للبرامج الـ 64-bit وx32dbg للـ 32-bit. افتح الـ sample في أداة زي DIE (Detect It Easy) الأول عشان تعرف نوعه.

نفس الكود بـ 4 أشكال syntax flavors

هتقابل نفس الـ instructions مكتوبة بأكتر من صيغة حسب الأداة. الكورس بيكتب NASM (أنظف صيغة Intel)، والمعمل بيقبل صيغة IDA/x64dbg كمان. أهم فرق: AT&T (الافتراضي في gdb/objdump) بيعكس ترتيب الـ operands.

قراية AT&T في 10 ثواني

(1) الاتجاه: source, destination (عكس Intel). (2) الـ registers قبلها % والأرقام قبلها $. (3) الحجم في آخر الـ mnemonic: b/w/l/q = 8/16/32/64. (4) الذاكرة: disp(base,index,scale). وفي gdb اكتب set disassembly-flavor intel وارتاح. IDA بيكتب المتغيرات المحلية بأسماء (var_8 = -8) — لما تشوف [rbp+var_8] اقراها [rbp-8].

مكتبة الطباعة بتاعة الكورس: io.inc helpers

طباعة رقم بالـ syscalls مش سهلة (لازم تحوّله لحروف — هنكتب ده بنفسنا في المرحلة 13). عشان كده الأمثلة اللي عليها علامة io بيتضاف لآخرها الكود ده أوتوماتيك. كله مكتوب بالـ instructions اللي هتتعلمها، ومافيهوش أي سحر — اقراه بعد ما تخلص الجزء التاني وهتفهمه كله:

print_hexrdi = الرقم0x…

⚠️
الدوال دي "مهذبة" زيادة عن اللزوم

دوال io.inc بتحافظ على كل الـ registers والـ flags عشان تسهّل عليك. الدوال الحقيقية (زي printf) مش كده: مسموحلها تبوّظ rax, rcx, rdx, rsi, rdi, r8–r11. هنتعلم القواعد دي في مرحلة الـ calling conventions — ومن ساعتها هتعامل كل call على إنها ممكن تبوّظ الـ registers دي.

برنامج بيستخدم io.inc RUN · DEBUG

default rel section .data title: db "countdown:", 0 section .text global _start _start: lea rdi, [title] call print_str call print_nl mov ebx, 5 ; counter (rbx survives calls in real ABIs too) .next: mov edi, ebx call print_int ; print the counter call print_nl dec ebx ; ebx = ebx - 1, sets ZF when it reaches 0 jnz .next ; loop while ebx != 0 mov edi, 0 call exit

في الـ 🔬 Debug: اضغط F8 (Step Over) على كل call print_int عشان متدخلش جوه المكتبة، وراقب rbx بيقل والـ ZF بيبقى 1 لما يوصل صفر فالـ jnz مبيقفزش.
