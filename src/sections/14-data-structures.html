Arrays وStructs والـ Linked Lists: استرجاع شكل البيانات

في الـ binary مفيش struct ولا أسماء fields — فيه offsets بس: [rcx+18h]، [rax+rdx*8+10h]. نص شغل الـ reverser هو إنه يجمع الـ offsets دي من دوال كتير ويبني منها الـ struct الأصلي (config الـ malware، packet الـ C2، جدول الأوامر). المرحلة دي بتعلّمك تقرا الـ "بصمة" دي.

الـ Structs: الـ layout والـ padding alignment rules

الـ compiler بيرص الـ fields بالترتيب، بس كل field لازم يبدأ عند offset بيقبل القسمة على حجمه (int على 4، pointer على 8)، فبيضيف padding. وحجم الـ struct كله بيتقرّب لمضاعف أكبر alignment فيه (عشان الـ arrays). شوف:

struct conn { char flag; int port; short type; char *host; long timeout; }; int get_port(struct conn *c) { return c->port; } char *nth_host(struct conn *arr, int i) { return arr[i].host; } int grid_get(int g[][10], int r, int c) { return g[r][c]; } struct node { struct node *next; int value; }; int list_sum(struct node *p) { int s = 0; while (p) { s += p->value; p = p->next; } return s; }

ولما الـ loop تمشي على array of structs، الـ compiler غالبًا بيحوّلها لـ pointer بيزيد بـ حجم الـ struct كل لفة (add rdi, 32) والـ field عند offset ثابت ([rdi+24]). لو شفت add reg, N في آخر loop وكل القرايات من نفس الـ reg بـ offsets ثابتة ← N = حجم الـ struct:

struct conn { char flag; int port; short type; char *host; long timeout; }; long total_timeout(struct conn *arr, int n) { long t = 0; for (int i = 0; i < n; i++) t += arr[i].timeout; return t; }

Struct Recovery: إزاي تبني الـ struct من الـ binary RE workflow

01

اجمع الـ offsets

كل وصول بنفس الـ base register: [rcx+4] (dword)، [rcx+8] (word)، [rcx+10h] (qword pointer)… الحجم من الـ register أو dword ptr، والنوع من الاستخدام (pointer لو اتعمله dereference، signed لو movsx).

02

اعرف الحجم

من الـ malloc(0x20) / HeapAlloc اللي اتعمل بيه، أو من الـ stride في الـ loops (shl 5، add rdi, 20h)، أو من memset(p, 0, 0x20).

03

اعمله في الأداة

IDA: Structures window (Shift+F9) أو Local Types؛ Ghidra: Data Type Manager أو "Auto Create Structure" على الـ parameter. وبعدين طبّقه على الـ pointer (T في IDA) — كل [rcx+10h] هتتحول لـ conn->host.

04

سمّي بالمعنى

field بيتمرر لـ connect() كـ port ← سمّيه port. field بيتقارن بـ أرقام أوامر ← cmd_id. الـ struct اللي اتبنى صح بيخلي الـ pseudo-code يتقري كأنه source.

🦠
الـ config struct

أغلب الـ malware عنده struct للـ config (C2 hosts، ports، sleep interval، mutex name، encryption key) بيتفك من الـ resources أو الـ .data في أول التشغيل. لو بنيت الـ struct ده صح، استخراج الـ IOCs بقى كتابة config extractor بسيط (Python) — ده شغل يومي في الـ threat intel.

الـ Linked Lists 🎬 scene

أهم loop هتشوفها: p = p->next = mov rdi, [rdi]. Windows نفسه مبني على doubly-linked lists (LIST_ENTRY): قايمة الـ modules في الـ PEB، الـ processes في الـ kernel (EPROCESS.ActiveProcessLinks — اللي الـ rootkits بتفكها عشان تخبّي process: DKOM).

section .data node_a: dq node_b, 10 ; { next, value } node_c: dq 0, 12 ; stored BEFORE node_b on purpose node_b: dq node_c, 20 section .text list_sum: ; rdi = head xor eax, eax test rdi, rdi je .done .next: add eax, [rdi+8] ; value mov rdi, [rdi] ; p = p->next test rdi, rdi jne .next .done: ret
