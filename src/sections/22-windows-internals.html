Windows Internals للـ Reverse Engineer

الـ malware المحترف مش بيستورد APIs بالطريقة العادية — بيلاقي الـ DLLs بنفسه من الـ PEB، يقرا الـ export tables، يحسب hashes بدل الأسماء، وأحيانًا يكلّم الـ kernel مباشرة. لو فهمت الطبقات دي هتعرف تفك أصعب أجزاء الـ loaders والـ shellcode في دقايق بدل أيام.

shellcode x64 بيبدأ بـ mov rax, gs:[60h] ثم mov rax, [rax+18h]. هو رايح لفين؟ الـ TEB ثم الـ stack الـ PEB ثم BeingDebugged الـ PEB ثم الـ Ldr — هيمشي على قايمة الـ modules عشان يلاقي kernel32/ntdll الـ IAT PEB+0x18 = Ldr. لو كان movzx eax, byte [rax+2] كان هيبقى BeingDebugged. شوف جدول الـ PEB. في export lookup لقيت الاسم المطلوب عند index i = 57 في AddressOfNames. الخطوة الصح؟ ord = AddressOfNameOrdinals[57] ثم AddressOfFunctions[ord] AddressOfFunctions[57] مباشرة AddressOfFunctions[57 − Base] GetProcAddress(57) جدول الأسماء متسورت أبجديًا، وجدول الدوال بترتيب الـ ordinals — جدول NameOrdinals هو الجسر. الترتيبين مختلفين. في loader لقيت mov r9d, 40h / mov r8d, 3000h / mov edx, 2C00h / xor ecx, ecx / call rax. أرجح API وتفسير؟ CreateFileA لملف حجمه 0x2C00 RegSetValueEx VirtualProtect لـ RX VirtualAlloc(NULL, 0x2C00, MEM_COMMIT|MEM_RESERVE, PAGE_EXECUTE_READWRITE) — بيجهّز مكان لـ payload حجمه ~11KB هيتنفّذ الـ 4 args بالترتيب (rcx, rdx, r8, r9) + الثوابت = توقيع واضح. وcall rax = العنوان جه من resolver (API hashing). 0x3000 و0x40 = ؟ جوه EXE (مش ntdll) لقيت: 4C 8B D1 B8 26 00 00 00 0F 05 C3. ده: كود ntdll طبيعي direct syscall stub بـ SSN = 0x26 — بيتخطى hooks الـ EDR Heaven's Gate shellcode decoder mov r10, rcx / mov eax, 0x26 / syscall / ret. دوّر على رقم 0x26 في جدول SSNs لإصدار Windows المستهدف عشان تعرف الـ Nt function. فكّ الـ bytes: 4C 8B D1 = mov r10, rcx… اكتب get_proc: rdi = base لـ DLL في الذاكرة، rsi = اسم دالة (NUL-terminated). امشي على الـ export table وارجع rax = base + RVA الدالة، أو 0 لو مش موجودة. (export dir RVA = [NT + 0x88] حيث NT = base + e_lfanew؛ NumberOfNames +0x18، Functions +0x1C، Names +0x20، NameOrdinals +0x24.) لازم تحافظ على rbx لو استخدمته. get_proc: xor eax, eax ret get_proc: ; rdi = module base, rsi = wanted name push rbx mov eax, [rdi+0x3C] ; e_lfanew mov eax, [rdi+rax+0x88] ; export directory RVA (PE32+) lea rbx, [rdi+rax] ; rbx = IMAGE_EXPORT_DIRECTORY mov ecx, [rbx+0x18] ; NumberOfNames mov r8d, [rbx+0x20] ; AddressOfNames (RVA) add r8, rdi xor r9d, r9d ; i = 0 .next_name: cmp r9d, ecx jae .not_found mov eax, [r8+r9*4] ; RVA of name i lea r10, [rdi+rax] mov r11, rsi .cmp: mov al, [r10] cmp al, [r11] jne .skip test al, al jz .found ; both strings ended together inc r10 inc r11 jmp .cmp .skip: inc r9d jmp .next_name .found: mov eax, [rbx+0x24] ; AddressOfNameOrdinals add rax, rdi movzx eax, word [rax+r9*2] ; ordinal index of name i mov edx, [rbx+0x1C] ; AddressOfFunctions add rdx, rdi mov eax, [rdx+rax*4] ; function RVA add rax, rdi pop rbx ret .not_found: xor eax, eax pop rbx ret احسب djb2 للـ string في rdi: h = 5381، ولكل byte: h = h*33 + c (32-bit). رجّعه في eax. ممنوع mul/imul — استخدم shl + add (h*33 = (h<<5) + h)، بالظبط زي ما هتلاقيه في الـ samples. djb2: mov eax, 5381 ret djb2: mov eax, 5381 ; 0x1505 - the djb2 fingerprint .next: movzx ecx, byte [rdi] test ecx, ecx jz .done mov edx, eax shl eax, 5 ; h*32 add eax, edx ; + h = h*33 add eax, ecx ; + c inc rdi jmp .next .done: ret resolver فيه: mov eax, 811C9DC5h ثم loop: xor al, [rcx] ثم imul eax, eax, 1000193h. اسم الخوارزمية؟ بص على جدول الـ hashes. FNV-1a (32-bit): offset basis 0x811C9DC5 وprime 0x01000193. الـ XOR قبل الضرب = «1a» (في FNV-1 الضرب الأول). stub في EXE: 4C 8B D1 B8 26 00 00 00 0F 05 C3. رقم الـ syscall (SSN)؟ B8 = mov eax, imm32 (little-endian). B8 26 00 00 00 = mov eax, 0x26. الـ SSN = 0x26. loader بيعمل djb2 لكل export في kernel32 ويقارن بـ 0x382C0F97. أنهي API؟ (حل المعمل djb2 فوق، وجرّب أسماء الـ APIs اللي بتستخدم للـ shellcode loading.) جرّبه في المعمل على أسماء: VirtualAlloc، VirtualProtect، CreateThread… djb2("VirtualAlloc") = 0x382C0F97. وده بالظبط شغل HashDB: يحسب الـ hash لكل export ويطابق. shellcode 32-bit: mov eax, fs:[30h] / mov eax, [eax+0Ch] / mov esi, [eax+14h] / lodsd / xchg eax, esi / lodsd / mov ebx, [eax+??]. الـ ?? كام عشان ebx = DllBase بتاع kernel32؟ شوف عمود x86 في جدول الـ PEB. 0x10: في x86 الـ InMemoryOrderLinks عند entry+8 والـ DllBase عند entry+0x18 ← الفرق 0x10.
