برامج Linux كاملة: الـ syscalls والـ I/O الحقيقي

من غير libc، البرنامج بيكلم الـ kernel مباشرة. ده بالظبط اللي بيعمله الـ shellcode، والـ malware الـ statically linked على Linux (botnets زي Mirai)، وأي كود عايز يتهرب من الـ hooks. في المرحلة دي هتكتب بنفسك اللي io.inc كان بيعمله: تحويل الأرقام لنص والعكس، وقراية input حقيقي.

الأخطاء = أرقام سالبة

الـ syscall مبترجعش -1 وerrno زي libc — بترجع −errno مباشرة في rax: −2 = ENOENT (الملف مش موجود)، −13 = EACCES، −14 = EFAULT (pointer غلط). يعني الفحص الصح: test rax, rax + js error. والـ syscall بتبوّظ rcx وr11 دايمًا.

section .data prompt: db "user: " plen equ $ - prompt section .bss buf: resb 32 section .text global _start _start: mov eax, 1 ; write(1, prompt, plen) mov edi, 1 lea rsi, [rel prompt] mov edx, plen syscall ; rax = 6, rcx/r11 destroyed mov eax, 39 ; getpid() syscall ; rax = pid xor eax, eax ; read(0, buf, 32) xor edi, edi lea rsi, [rel buf] mov edx, 32 syscall ; rax = bytes read (6: "admin\n") mov eax, 1 ; echo it back mov edi, 1 lea rsi, [rel buf] mov edx, 6 syscall mov eax, 60 xor edi, edi syscall

من رقم لنص: اكتب itoa بنفسك print_uint من جوه

الشاشة مبتعرفش أرقام — بتعرف حروف. عشان تطبع 1234 لازم تطلّع الأرقام: 1234 % 10 = 4، 123 % 10 = 3… وبتطلع بالمقلوب، فبنكتبها في buffer من آخره لأوله. وده بالظبط اللي في print_uint:

; print an unsigned number without any library default rel section .bss digits: resb 32 section .text global _start _start: mov rax, 9876543210 call print_u64 mov eax, 60 xor edi, edi syscall print_u64: ; prints rax in decimal + '\n' lea rsi, [digits + 31] mov byte [rsi], 10 ; '\n' at the very end mov ecx, 10 .next: xor edx, edx div rcx ; rax = rax / 10, rdx = last digit add dl, '0' ; digit -> ASCII dec rsi mov [rsi], dl ; fill the buffer backwards test rax, rax jnz .next lea rdx, [digits + 32] sub rdx, rsi ; length = end - start mov eax, 1 ; write(1, rsi, rdx) mov edi, 1 syscall ret

شكل الـ itoa في أي binary

loop فيها قسمة على 10 (أو الـ magic 0xCCCCCCCD!) + add …, 30h + كتابة لورا في buffer = تحويل رقم لـ string. والعكس (sub …, 30h + ضرب في 10 + جمع) = atoi. أول ما تعرف الـ pattern، سمّي الدالة وكمّل — متضيعش وقت تحللها سطر سطر.

من نص لرقم: atoi + قراية stdin parsing

البرنامج ده بيقرا رقم من stdin (زي ما الـ malware بيقرا config أو أمر من socket)، يحوّله لرقم، ويطبع مربعه. لاحظ الـ parsing: result = result × 10 + (c − '0') لحد أول حرف مش رقم:

default rel section .bss line: resb 64 section .text global _start _start: xor eax, eax ; read(0, line, 64) xor edi, edi lea rsi, [line] mov edx, 64 syscall lea rdi, [line] call atoi ; rax = number imul rax, rax ; square it mov rdi, rax call print_int ; 1522756 call print_nl xor edi, edi call exit atoi: ; rdi = text, returns rax xor eax, eax .digit: movzx ecx, byte [rdi] sub ecx, '0' cmp ecx, 9 ja .done ; not a digit (unsigned trick: catches < '0' too) imul rax, rax, 10 add rax, rcx inc rdi jmp .digit .done: ret

الأرقام مختلفة تمامًا! (eax = 1 في 32-bit = exit مش write.) والفخ: int 0x80 شغالة حتى في برنامج 64-bit، بس بتاخد 32 bit بس من كل pointer — فأي عنوان فوق 4 GB (زي الـ stack 0x7FFF…) بيتقص ويطلع EFAULT. جرّب في المعمل:

section .data msg: db "from .data (low address) works", 10 len equ $ - msg section .text global _start _start: mov eax, 4 ; 32-bit ABI: 4 = write mov ebx, 1 ; fd lea rcx, [rel msg] ; 0x402000 fits in 32 bits -> OK mov edx, len int 0x80 push 0x0A4B4F ; "OK\n" on the stack (0x7FFF... address) mov eax, 4 mov ebx, 1 mov rcx, rsp ; only ecx is used -> address truncated! mov edx, 3 int 0x80 ; rax = -14 (EFAULT) mov eax, 1 ; 32-bit ABI: 1 = exit xor ebx, ebx int 0x80

تعرّف على shellcode الـ Linux من نظرة

الشكل ده (أو تنويعاته) هتقابله في exploits وفي الـ payloads: xor eax, eax · push rax · mov rbx, 68732F2F6E69622Fh ("/bin//sh") · push rbx · mov rdi, rsp · xor esi, esi · xor edx, edx · mov al, 3Bh · syscall = execve("/bin//sh", 0, 0). الـ // عشان الطول يبقى 8 بالظبط، وmov al بدل mov eax عشان مفيش null bytes. ولو قبلها socket/connect/dup2 × 3 = reverse shell.

✏️ تمارين المرحلة 13

في Linux x64، الـ argument الرابع لـ syscall بيتحط في: rcx r10 r8 rdx r10 — مش rcx زي الدوال العادية، لأن الـ syscall instruction بتكتب RIP في rcx. الـ syscall بتبوّظ rcx فمينفعش يبقى argument. open رجّعت rax = 0xFFFFFFFFFFFFFFFE. ده معناه: الـ fd رقم ضخم نجحت الملف اتفتح للقراية بس فشلت: −2 = ENOENT (الملف مش موجود) القيم من −1 لـ −4095 = أخطاء. لازم تفحص الإشارة. القيمة دي كـ signed كام؟ sample لـ Linux بيعمل mmap بـ rdx = 7. الـ 7 دي: PROT_READ | PROT_WRITE | PROT_EXEC — ذاكرة RWX (🚩 غالبًا shellcode/unpacking) حجم الذاكرة رقم الـ fd flags الـ sharing READ=1، WRITE=2، EXEC=4. المجموع 7 = كل الصلاحيات. الـ arg التالت لـ mmap = prot، وهو bit flags. برنامج 32-bit بيعمل mov eax, 1 ثم int 0x80. ده: write read exit fork في الـ 32-bit ABI: 1 = exit، 3 = read، 4 = write، 11 = execve. مختلفة عن الـ 64-bit! جدول الـ 32-bit مختلف. في loop لقيت sub ecx, 30h ثم cmp ecx, 9 ثم ja done ثم imul eax, eax, 10 ثم add eax, ecx. ده: itoa atoi (تحويل نص لرقم) تشفير strlen كل حرف بيتحول لرقم ويتضاف للنتيجة × 10. الـ ja بعد الطرح (unsigned) بتمسك أي حرف مش رقم بمقارنة واحدة. 0x30 = '0'. بيحوّل حرف لرقم ويبني النتيجة. malware على Linux بيعمل ptrace(PTRACE_TRACEME, 0, 0, 0) ولو رجعت −1 (أو سالب) بيخرج. ليه؟ عشان يعمل fork عشان يقرا ذاكرته عشان يرفع الصلاحيات anti-debugging: process واحد بس يقدر يعمل trace — لو gdb شغّال عليه، النداء بيفشل تكنيك كلاسيكي. الحل: patch للـ jump، أو catch syscall في gdb وتغيير rax لصفر. ptrace = الـ API اللي gdb نفسه بيستخدمها. من غير io.inc: اطبع rax = 1234567 متبوع بسطر جديد، واخرج بـ exit(0).
