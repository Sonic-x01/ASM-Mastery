صيغة PE (وELF): تشريح الملف التنفيذي

قبل ما تقرا instruction واحدة، الـ header بيقولك حاجات كتير: 32 ولا 64، EXE ولا DLL، بيستورد إيه من APIs، فيه sections غريبة؟ packed؟ مكتوب إمتى؟ وكمان الـ malware نفسه بيقرا الـ PE headers وهو شغال (reflective loading، البحث عن APIs في الذاكرة). المرحلة دي هتشرّح ملف EXE حقيقي byte byte.

PE Explorer: ملف EXE حقيقي تفاعلي

ده ملف Windows x64 حقيقي (2560 byte) — نسخة من برنامج الـ WinAPI بتاع المرحلة 15 مع MessageBox. اتعمله link بـ MinGW. دوس على أي field تشوف الـ bytes بتوعه والمعنى، أو دوس على أي byte تعرف هو بتاع إيه. وجرّب المحوّل تحت: 0x140004080 أو 0x3000.

Exports

الـ DLL بيصدّر دوال بالاسم أو بالرقم (ordinal). malware DLL ممكن يتشغّل بـ rundll32 evil.dll,Start ← الـ export ده هو الـ entry الحقيقي. وforwarded exports + DLL بنفس اسم DLL شرعي = DLL side-loading/proxying.

🎁

Resources والـ Overlay

.rsrc فيه الأيقونات والـ version info — وكتير payload متشفر (FindResource + LoadResource في الـ imports = شك). الـ overlay = بيانات بعد آخر section (installers، droppers، signatures).

🧵

TLS · Relocations · Exceptions

TLS directory = callbacks قبل الـ entry. .reloc = أماكن العناوين المطلقة (بيستخدمها الـ manual mapper في الـ malware). .pdata في x64 = بداية ونهاية كل دالة (بيساعد IDA يلاقي الدوال).

🧾

Rich header وDebug directory

الـ Rich header (MSVC) = بصمة لإصدارات أدوات البناء — بيربط samples ببعض. الـ Debug directory فيه مسار الـ PDB: C:\Users\dev\source\repos\stealer\Release\stealer.pdb — حصلت كتير!

📦
علامات الـ Packing

(1) entropy عالية (~7.9) في section. (2) section بـ RawSize صغير أو صفر وVirtualSize كبير (هيتفك فيه). (3) section صلاحياته RWX. (4) أسماء sections غريبة (UPX0، .aspack، أسماء عشوائية). (5) imports قليلة جدًا (LoadLibrary/GetProcAddress/VirtualAlloc). (6) entry point برا .text. (7) strings قليلة جدًا. الحل: unpacking — breakpoint على الـ OEP بعد الفك ثم dump + Scylla (المرحلة 24).

الـ disassembler بيقولك الـ string عند 0x140002019. عايز تعدّلها بالـ hex editor. محتاج: تروح لـ offset 0x140002019 في الملف تروح لـ offset 0x2019 تحوّل لـ RVA (0x2019) وبعدين لـ file offset بالـ section table (0x2019 − 0x2000 + 0x600 = 0x619) مينفعش تتعدل VA → RVA (اطرح ImageBase) → file offset (بالـ section). جرّبها في المحوّل. VA ≠ RVA ≠ file offset. sample فيه section اسمه .text بس VirtualSize = 0x58000 وSizeOfRawData = 0 وصلاحياته RWX. ده غالبًا: packer: الـ section فاضي على الـ disk وهيتملي بالكود المفكوك وقت التشغيل ملف تالف الـ .bss debug build UPX مثلًا: UPX0 فاضي (RawSize 0) وUPX1 فيه البيانات المضغوطة + الـ stub. RawSize = 0 معناه إيه؟ الـ imports كلها: LoadLibraryA، GetProcAddress، VirtualAlloc، ExitProcess. الاستنتاج الأقوى؟ برنامج بسيط ومش ضار برنامج .NET driver الـ APIs الحقيقية بتتحل وقت التشغيل (packed أو shellcode loader) — الـ imports مش بتقول القصة كاملة دوّر على strings أسماء APIs أو hashes (مرحلة 22)، أو شغّله واعمل breakpoint على GetProcAddress تشوف بيطلب إيه. برنامج حقيقي بيستخدم APIs كتير — فين هما؟ في dump للذاكرة، الـ IAT slot بتاع CreateFileW بيشاور على عنوان جوه heap مش جوه kernel32. ده: طبيعي مع ASLR IAT hook: حد (malware أو EDR) غيّر الـ slot لدالته الدالة forwarded bug في الـ dump الـ slot السليم بيشاور جوه الـ DLL صاحبة الدالة (أو forward لـ DLL تانية). عنوان في heap/private memory = hook. شوف آخر خطوة في مشهد الـ IAT. في ELF: call puts@plt. الـ .plt entry بيعمل: بينفذ puts جوه الملف syscall مباشر jmp [puts@GOT] — أول مرة الـ GOT بيرجّعه للـ resolver اللي بيحل العنوان ويكتبه في الـ GOT (lazy binding) بيحمّل libc نفس فكرة الـ IAT + import thunks في الـ PE (اللي شفتها في الملف: FF 25 jmp [IAT]). PLT/GOT = مقابل الـ IAT. الـ malware (reflective loaders، والـ shellcode اللي بيدوّر على kernel32) بيقرا الـ PE headers من الذاكرة بنفسه. اكتب دالة: rdi = base لصورة PE في الذاكرة. اتأكد من MZ (0x5A4D كـ word)، اقرا e_lfanew من [base+0x3C]، اتأكد من التوقيع PE\0\0 (0x00004550 كـ dword)، ورجّع NumberOfSections (word عند +6 من التوقيع) في eax. لو أي check فشل رجّع -1. pe_num_sections: mov eax, -1 ret pe_num_sections: cmp word [rdi], 0x5A4D ; 'MZ' jne .bad mov eax, [rdi+0x3C] ; e_lfanew cmp dword [rdi+rax], 0x4550 ; 'PE\0\0' jne .bad movzx eax, word [rdi+rax+6] ; FileHeader.NumberOfSections ret .bad: mov eax, -1 ret من الـ PE Explorer: أول instruction هتتنفذ عند أنهي VA؟ ImageBase + AddressOfEntryPoint. 0x140000000 + 0x1000 = 0x140001000 (لو مفيش ASLR relocation). عنوان الـ MessageBox title ("ASM Mastery") في الكود = 0x140002019. هتلاقيه عند أنهي file offset؟ RVA 0x2019 في .rdata (VirtualAddress 0x2000، PointerToRawData 0x600). 0x2019 − 0x2000 + 0x600 = 0x619. دوس على الـ byte ده في الـ hex view — هتلاقي 41 53 4D = "ASM". call [rip+0x304B] عند 0x14000102F (طولها 6 bytes). بتقرا العنوان من أنهي VA؟ (وده slot أنهي دالة؟ اتأكد من الـ explorer.) 0x14000102F + 6 + 0x304B. 0x140001035 + 0x304B = 0x140004080 = IAT slot بتاع WriteFile. الـ TimeDateStamp بتاع الملف بيقول إنه اتعمله link سنة كام؟ File Header › TimeDateStamp. 0x6553F100 = 2023-11-14 22:13:20 UTC. (اتظبط عمدًا في الملف ده — وده بالظبط ليه متثقش فيه 100% في الـ malware.) ملف تاني: ImageBase = 0x140000000. الـ section .data: VirtualAddress = 0x5000، PointerToRawData = 0x3A00. الـ key المشفر عند VA 0x140005123. الـ file offset؟ اطرح ImageBase الأول. RVA = 0x5123 ← 0x5123 − 0x5000 + 0x3A00 = 0x3B23.
