Shellcode: كتابته، تحميله، وتحليله

الـ shellcode = machine code مستقل: مالوش headers ولا imports ولا عنوان ثابت، بيتحط في أي حتة في الذاكرة ويشتغل. بتلاقيه في الـ exploits، الـ macros، الـ loaders، الـ beacons (Cobalt Strike)، وفي الـ memory dumps. هتكتب واحد حقيقي، تشغّله بـ loader، تشفّره، وبعدين تتعلم تحلل اللي بتلاقيه.

📍

Position-independent

مفيش عناوين مطلقة: كل حاجة نسبية ([rip+x]، الـ stack، أو GetPC). لازم يشتغل سواء اتحط في 0x1F0000 أو 0x7FF6….

🚫

من غير imports

بيلاقي الـ APIs بنفسه: PEB walk ← export table ← hash (المرحلة 22). على Linux أسهل: syscall مباشرة.

0️⃣

من غير null bytes (غالبًا)

لو هيعدّي من strcpy أو string في exploit، أي 00 هيقطعه. فبيستخدم xor eax, eax، push imm8 / pop، وregisters صغيرة بدل mov eax, 1 (B8 01 00 00 00).

🪶

صغير وstaged

stager صغير (مئات الـ bytes) بيحمّل stage كبير من الشبكة ويحطه في الذاكرة. الـ stage ممكن يبقى DLL كامل بيتحمّل reflectively.

أول shellcode ليك (Linux x64، null-free)

; 42 bytes, no 0x00 anywhere - press "Bytes" and check global _start _start: mov rax, 0x0A293A206D736120 ; " asm :)\n" (pushed first = higher address) push rax mov rax, 0x79622064656E7770 ; "pwned by" push rax ; rsp -> "pwned by asm :)\n" (string on the stack) push 1 pop rax ; rax = 1 (write) 6A 01 58 instead of B8 01 00 00 00 mov edi, eax ; fd = 1 mov rsi, rsp ; buf = the stack push 16 pop rdx ; len = 16 syscall push 60 pop rax ; exit xor edi, edi syscall

الـ string اتبنت على الـ stack بـ 2 mov rax, imm64 + push (نفس فكرة الـ stack strings في المرحلة 16) — مفيش .data ولا عنوان ثابت. وده الـ loader: برنامج C بياخد الـ 42 byte دول ويشغّلهم:

نفس الـ loader على Windows

VirtualAlloc(NULL, len, 0x3000, 0x40) ← memcpy (أو RtlMoveMemory) ← ((void(*)())p)() أو CreateThread(…, p, …) + WaitForSingleObject(h, INFINITE). الأذكى: RW ثم VirtualProtect لـ RX. وأي حاجة من دول في sample = shellcode loader — الـ payload الحقيقي هو الـ buffer اللي بيتنسخ: اعمل breakpoint على الـ call واعمل dump له.

Decoder stub: shellcode بيفك نفسه ASM Explorer

; the same payload, XOR-encoded with 0xAA, behind a null-free decoder stub section .shell progbits alloc exec write align=16 ; RWX: the stub rewrites its own bytes global _start _start: jmp short get_payload decoder: pop rsi ; rsi = address of payload (GetPC) push 42 pop rcx ; rcx = length, no 0x00 bytes .l: xor byte [rsi+rcx-1], 0xAA ; decode in place, last byte first loop .l jmp rsi ; run the decoded shellcode get_payload: call decoder ; pushes the address of the next byte = payload payload: db 0xE2, 0x12, 0x8A, 0xCB, 0xD9, 0xC7, 0x8A, 0x90, 0x83, 0xA0, 0xFA, 0xE2, 0x12, 0xDA db 0xDD, 0xC4, 0xCF, 0xCE, 0x8A, 0xC8, 0xD3, 0xFA, 0xC0, 0xAB, 0xF2, 0x23, 0x6D, 0xE2 db 0x23, 0x4C, 0xC0, 0xBA, 0xF0, 0xA5, 0xAF, 0xC0, 0x96, 0xF2, 0x9B, 0x55, 0xA5, 0xAF

Carve

2

Identify

32 ولا 64؟ فين نقطة البداية؟ دوّر على التوقيعات تحت (GetPC، PEB access، الـ prologue المشهور). CyberChef «Disassemble x86» لنظرة سريعة.

3

Emulate

speakeasy (Mandiant) وscdbg بيشغّلوا الـ shellcode في بيئة مزيفة ويطبعوا كل API اتنادت بالـ args — في دقيقة بتعرف الـ C2 والـ URLs.

4

Debug / Disassemble

BlobRunner أو shellcode2exe ← x64dbg. أو IDA/Ghidra: load كـ binary خام بالمعمارية الصح وابدأ من offset 0 (C).

✏️ تمارين المرحلة 23

ليه الـ shellcode بيكتب push 60 / pop rax بدل mov eax, 60؟ أسرع أصغر بـ 10 bytes mov eax, 60 = B8 3C 00 00 00 فيها 3 null bytes — 6A 3C 58 مفيهاش عشان rax 64-bit الـ null bytes بتقطع الـ shellcode لو اتعدّى كـ C string. push imm8 + pop = 3 bytes ونضيفة. اكتب الـ bytes بتاعة الاتنين. في الـ jmp-call-pop، بعد call decoder وpop rsi، الـ rsi بيشاور على: أول byte بعد الـ call = الـ payload المشفر بداية الـ decoder الـ stack نهاية الـ payload الـ call حطت «عنوان الرجوع» = اللي بعدها مباشرة، وده مش كود: ده الـ payload. call بتعمل push لإيه؟ loader بيعمل VirtualAlloc (RW)، ثم XOR loop على buffer، ثم VirtualProtect(p, len, 0x20, …)، ثم call rax. أسرع طريقة تجيب الـ payload المفكوك؟ تفك الـ XOR بإيدك breakpoint على VirtualAlloc تدوّر على strings breakpoint على VirtualProtect (أو على الـ call rax) وdump للـ buffer — هو اتفك خلاص خلّي الـ malware يعمل الشغل. الـ VirtualProtect لـ RX (0x20) = «الكود جاهز للتشغيل». استنى لحد ما يتفك. EDR شاف: VirtualAllocEx + WriteProcessMemory + CreateRemoteThread من process لـ explorer.exe. ده: تحديث Windows classic remote process injection DLL side-loading persistence التلاتة دول بالترتيب = التوقيع الأشهر. البدائل: QueueUserAPC، SetThreadContext، hollowing… شوف مشهد الـ injection. الـ stager أحيانًا مايعرفش الـ payload الكبير اتحط فين في الذاكرة — فبيدوّر على علامة (egg) قبله: الـ 8 bytes "w00tw00t". اكتب egg_hunt: rdi = بداية المنطقة، rsi = طولها. رجّع في rax عنوان أول byte بعد الـ egg، أو 0 لو مش موجود. (تلميح: الـ egg كـ qword little-endian = 0x7430307774303077، وآخر مكان ممكن يبدأ فيه = rdi + rsi − 8.) egg_hunt: xor eax, eax ret egg_hunt: mov rax, 0x7430307774303077 ; "w00tw00t" lea rdx, [rdi+rsi-8] ; last possible start .scan: cmp rdi, rdx ja .none cmp [rdi], rax ; compare 8 bytes at once je .found inc rdi jmp .scan .found: lea rax, [rdi+8] ; payload starts right after the egg ret .none: xor eax, eax ret shellcode Linux x64 بيخلص بـ: 6A 3B / 58 / 99 / 0F 05. أنهي syscall؟ (اكتب اسمها) push 0x3B / pop rax / cdq / syscall. الـ 59 في جدول Linux x64… rax = 0x3B = 59 = execve (وcdq = rdx = 0 = envp NULL). غالبًا execve("/bin//sh", …) — الـ // عشان الـ string تبقى 8 bytes بالظبط. decoder بيعمل xor byte [rsi+rcx-1], 5Ah، وأول byte في الـ payload المشفر 0x12. قيمته بعد الفك؟ 0x12 ^ 0x5A. 0x12 ^ 0x5A = 0x48 = REX.W — بداية منطقية لـ shellcode x64 (48 …). لو المفتاح اللي جربته طلّع bytes «منطقية» زي 48/4C/E8/FC يبقى غالبًا صح. buffer في memory dump بيبدأ بـ: FC 48 83 E4 F0 E8 C0 00 00 00 41 51 41 50 52 51 56 48 31 D2 65 48 8B 52 60. آخر instruction (65 48 8B 52 60) بتقرا أنهي structure؟ 65 = gs prefix، و rdx = 0 من الـ xor اللي قبلها. mov rdx, gs:[rdx+60h] مع rdx = 0 ← PEB. ده الـ block_api بتاع Metasploit/Cobalt Strike x64: هيمشي على الـ Ldr ويحسب ROR13 hashes للـ modules والـ exports (المرحلة 8 و22).
