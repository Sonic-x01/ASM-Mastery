ARM64: نفس الأفكار، لغة تانية

IoT malware (Mirai وعائلته على الراوترات والكاميرات)، native libraries في تطبيقات Android، وmalware الـ macOS على Apple Silicon — كلهم ARM. الخبر الحلو: كل اللي اتعلمته (stack، calling conventions، loops، structs، idioms) بينطبق؛ اللي بيتغير هو «النطق». المرحلة دي قاموس x86 ⇄ ARM64.

مفيش أطوال متغيرة ← مفيش desync ولا anti-disassembly بالقفز لنص instruction. الـ disassembly الخطي دايمًا صح.

ARM في التحليل العملي

IoT: ELF ARM32 (فيه وضع Thumb بـ instructions 2 bytes — الـ disassembler لازم يعرف) أو ARM64، غالبًا statically linked وstripped — FLIRT/Function ID مهمين جدًا. Android: lib*.so جوه الـ APK (lib/arm64-v8a/)، والـ entry من Java عن طريق JNI_OnLoad وJava_com_pkg_Class_method. macOS: Mach-O (مش ELF)، والـ syscalls بـ svc #0x80 وx16. Ghidra وIDA بيدعموا الكل، وللـ dynamic: QEMU user-mode أو جهاز/emulator.

دالة ARM64 مفيهاش ولا stp ولا str للـ stack، وبتنتهي بـ ret. عنوان الرجوع فين؟ على الـ stack عند [sp] في x30 (LR) — دالة leaf مش محتاجة تحفظه في x29 في pc الـ bl حطه في x30، ومفيش bl جوه الدالة يمسحه، فـ ret بتستخدمه على طول. bl بتكتب فين؟ adrp x0, 0x412000 ثم add x0, x0, #0x3A8. x0 = قيمة من الذاكرة 0x412000 0x3A8 0x4123A8 — عنوان (غالبًا string أو global) adrp بيجيب عنوان الصفحة (4KB)، وadd بيكمّل الـ offset جواها. IDA/Ghidra بيجمعوهم لك ويعرضوا الـ string. صفحة + offset. add w0, w0, w1 ثم b.eq L مباشرة. الـ b.eq هتعتمد على: flags قديمة من آخر instruction بتغير الـ flags (لأن add من غير s مبتلمسهاش) نتيجة الـ add w0 == w1 مش هتتنفذ في ARM الـ flags بتتغير بس مع adds/subs/cmp/tst… فرق مهم عن x86. الـ s suffix. في IoT sample: mov x8, #198 ثم svc #0 (Linux ARM64). المقابل في x86-64 Linux؟ مستحيل تعرف rax = 198 / syscall نفس الفكرة بس الأرقام مختلفة — 198 في ARM64 = socket (في x86-64 = 41). لازم جدول الـ syscalls الخاص بالمعمارية int 0x80 كل معمارية ليها جدول. ARM64 Linux: 198 socket، 203 connect، 221 execve، 64 write، 93 exit. الأرقام بتختلف بين المعماريات. الـ decoder ده اشتغل على 4 bytes: 32 29 14 13. الناتج (كنص)؟ decode: // x0 = buf, w1 = len cbz w1, .done mov w2, 0x5A // key .loop: ldrb w3, [x0] eor w3, w3, w2 // eor = xor strb w3, [x0], 1 // store, then x0 += 1 add w2, w2, 3 // rolling key subs w1, w1, 1 b.ne .loop .done: ret المفاتيح: 0x5A، 0x5D، 0x60، 0x63. 0x32^0x5A = 0x68 'h'، 0x29^0x5D = 0x74 't'، 0x14^0x60 = 0x74 't'، 0x13^0x63 = 0x70 'p' ← http. نفس منطق الـ XOR decoders اللي في x86 — بس eor وstrb …, 1 (post-index). دالة clamp من الـ compiled view: bic w0, w0, w0, asr #31 / mov w1, 255 / cmp w0, 255 / csel w0, w0, w1, le. الناتج لـ w0 = 300؟ csel w0, w0, w1, le = (le) ? w0 : w1. 300 موجب ← bic ملهاش تأثير. 300 > 255 ← الشرط le غلط ← w0 = w1 = 255. آخر shellcode ARM64 Linux: mov x0, #0 / mov x8, #93 / svc #0. أنهي syscall؟ شوف جدول المقارنة فوق. x8 = 93 = exit (و x0 = 0 = الكود). في x86-64 نفس الحاجة: rax = 60.
