الـ Registers: الـ 16 خانة اللي كل حاجة بتعدّي عليها

الـ registers هي "إيد" الـ CPU: أي حساب لازم يعدّي عليها تقريبًا. في الـ disassembly، تتبّع قيم الـ registers هو 80% من شغلك. المرحلة دي هتخليك تعرف كل register، أجزاؤه، القواعد الغريبة بتاعته، وإزاي تقراه في الـ debugger.

الأسماء الغريبة دي (accumulator، counter…) تاريخية. النهاردة كل الـ registers عامة تقريبًا، بس بعض الـ instructions لسه متمسكة بـ register معيّن (mul/div بـ rax وrdx، الـ shifts بـ cl، الـ string ops بـ rsi/rdi/rcx)، والـ calling conventions بتدي كل register دور ثابت. اسم الـ register بيقولك حجم العملية: r = 64، e = 32 (Extended)، من غير بادئة = 16، وl/h = 8.

🧹

الكتابة في 32-bit بتصفّر الباقي

mov eax, 5 ⇐ rax = 0x0000000000000005. الـ 32 bit العليا بتتصفر أوتوماتيك. ده قرار AMD عشان يمنع اعتمادية خفية على القيمة القديمة (أسرع للـ CPU).

🧩

الكتابة في 8/16-bit مبتلمسش الباقي

mov al, 5 ⇐ بيتغير أول byte بس، والـ 56 bit التانيين زي ما هما. نفس الكلام لـ ax وah. (ده سلوك قديم من أيام الـ 16-bit واتساب زي ما هو.)

النتيجة العملية في الـ disassembly:

  • xor eax, eax = rax = 0 (2 bytes بس: 31 C0) — أشهر idiom في x64. مش هتشوف mov rax, 0 تقريبًا أبدًا.
  • mov eax, edi قبل استخدام rax كـ index = تحويل unsigned int لـ 64-bit (zero-extend مجاني).
  • mov eax, eax = "صفّر النص العالي" — بتشوفها كتير قبل jump tables و array indexing.
  • أي دالة بترجع int بتكتب في eax، فالـ caller لو عايز 64-bit هيعمل movsxd rax, eax (لو signed).
partial: mov rax, 0x1122334455667788 mov al, 0xAA ; only bits 0-7 change mov ah, 0xBB ; only bits 8-15 change mov ax, 0xCCCC ; only bits 0-15 change mov eax, 0xDDDDDDDD ; bits 32-63 become ZERO! mov r9, -1 ; r9 = 0xFFFFFFFFFFFFFFFF mov r9b, 0 ; r9 = 0xFFFFFFFFFFFFFF00 mov r9d, r9d ; "self-move" clears the upper half xor ecx, ecx ; the idiom: rcx = 0 ret
⚠️
قيد الـ high-byte registers

ah/bh/ch/dh مينفعش يتجمعوا في instruction واحدة مع أي حاجة محتاجة REX prefix (يعني r8–r15، أو sil/dil/spl/bpl، أو operand 64-bit). mov ah, sil وmovzx rax, ah = خطأ. السبب في الـ encoding: نفس الـ bits اللي بتعني ah من غير REX بتعني spl مع REX. جرّب تكتبها في المعمل وشوف رسالة الخطأ.

🦠
أشهر سطرين في الـ shellcode والـ malware

mov rax, gs:[60h] (أو mov eax, fs:[30h] في 32-bit) = "هات عنوان الـ PEB". من الـ PEB الـ malware بيعرف هل فيه debugger (PEB.BeingDebugged عند offset 2)، وبيلاقي الـ DLLs المحمّلة عشان يجيب عناوين الـ APIs من غير ما يستورد حاجة. لما تشوف gs:[60h] اعرف إنك قدام كود "مش طبيعي" — هنفصّله في مرحلة Windows Internals.

الـ Registers التانية اللي هتقابلها SIMD · debug · control

🧮

XMM0–15 / YMM / ZMM

registers واسعة (128 / 256 / 512 bit) للـ floats والـ SIMD. الـ compilers بيستخدموها لـ memcpy وmemset السريعين ولفك التشفير المتوازي. xmm0 = القيمة الراجعة لو float/double.

🐞

DR0–DR7

Debug registers: DR0–DR3 بيشيلوا عناوين الـ hardware breakpoints، وDR7 بيتحكم فيهم. الـ malware بيقراهم بـ GetThreadContext عشان يكشف الـ debugger — anti-debugging كلاسيكي.

🔐

CR0 / CR3 / CR4

Control registers للـ kernel بس (Ring 0): CR3 = عنوان جدول الـ paging بتاع الـ process. هتشوفهم في تحليل الـ rootkits والـ drivers.

✏️ تمارين المرحلة 03

rax = 0x1122334455667788. بعد mov ax, 0، rax = ؟ 0x0000000000000000 0x1122334455660000 0x1122334400000000 0x0000000055660000 الكتابة في 16-bit بتغيّر آخر 16 bit بس. القاعدة: 32-bit بس هي اللي بتصفّر النص العالي. rax = 0x1122334455667788. بعد mov eax, 0، rax = ؟ 0x1122334400000000 0x1122334455667700 0x0000000000000000 نفس القيمة الكتابة في أي register 32-bit بتصفّر الـ 32 bit العليا. دي الكتابة الـ 32-bit — القاعدة الخاصة. على Linux x64، الـ argument الأول لأي دالة بيتحط في: rdi rcx rax على الـ stack System V ABI: rdi, rsi, rdx, rcx, r8, r9. على Windows: rcx, rdx, r8, r9. Linux و Windows مختلفين. على Linux بيبدأ بـ "destination index". أنهي instruction من دول مش هتتعمل assemble؟ mov al, bl mov ah, bl mov r8b, cl mov ah, r8b r8b محتاج REX، وah مينفعش مع REX. دوّر على الـ instruction اللي فيها high-byte register مع حاجة محتاجة REX. إيه أشهر طريقة يصفّر بيها الـ compiler register 64-bit؟ mov rax, 0 xor eax, eax sub rax, rax and rax, 0 2 bytes بس، والـ CPU بيتعرّف عليها كـ "zeroing idiom" ومبيستناش القيمة القديمة. وبتصفّر rax كله بسبب قاعدة الـ 32-bit. دوّر على أقصر encoding — وافتكر قاعدة الـ 32-bit. في sample 64-bit لـ Windows لقيت mov rax, qword ptr gs:[60h]. الكود ده بيجيب: الـ stack canary عنوان الـ main عنوان الـ PEB (Process Environment Block) الوقت الحالي gs:[60h] على x64 Windows = PEB. منه الـ malware بيكشف الـ debugger أو بيلف على الـ DLLs المحمّلة. على Windows x64، GS بيشاور على الـ TEB، وعند offset 0x60 فيه pointer لهيكل مهم جدًا للـ process. الـ malware بيقرا Dr0–Dr3 من الـ thread context. بيدوّر على إيه؟ hardware breakpoints حاطها الـ debugger الـ software breakpoints (int3) عدد الـ cores الـ encryption key لو أي واحد منهم مش صفر، فيه hardware breakpoint ⇐ غالبًا فيه analyst! الحل في x64dbg: plugins زي ScyllaHide أو إنك تستخدم software breakpoints في الأماكن دي. DR = Debug Registers. بيشيلوا عناوين من نوع معيّن من الـ breakpoints. بعد mov ecx, 0FFFFFFFFh، قيمة rcx؟ 0xFFFFFFFFFFFFFFFF -1 (64-bit) مش متحدد 0x00000000FFFFFFFF الكتابة 32-bit بتعمل zero-extension مش sign-extension. rcx = 4294967295. القاعدة بتصفّر، مبتنسخش الإشارة. إيه قيمة rax في الآخر؟ (اكتبها hex، والأصفار اللي على الشمال مش مهمة) trace: mov rax, 0x1111111111111111 mov eax, 0x22222222 mov ax, 0x3333 mov al, 0x44 mov ah, 0x55 ret سطر بسطر: الـ mov eax بيصفّر النص العالي، والباقي بيغيّر أجزاء صغيرة بس. 0x1111111111111111 ← mov eax ← 0x0000000022222222 ← mov ax ← 0x0000000022223333 ← mov al ← …3344 ← mov ah ← 0x0000000022225544. إيه قيمة rcx في الآخر؟ trace: mov rcx, -1 ; all ones mov cl, 0 mov ecx, ecx ret بعد السطر التاني: كل الـ bits واحد ما عدا أول byte. السطر التالت كتابة 32-bit… 0xFFFFFFFFFFFFFFFF ← mov cl, 0 ← 0xFFFFFFFFFFFFFF00 ← mov ecx, ecx بيكتب نفس الـ 32 bit السفلى (0xFFFFFF00) وبيصفّر العليا ← 0x00000000FFFFFF00. rax جاي فيه أي قيمة. خلّي أول byte = 0x41 ('A') من غير ما تغيّر أي bit تاني في rax. patch: mov eax, 0x41 ret patch: mov al, 0x41 ret ax فيه رقم 16-bit زي 0x1234. خلّيه 0x3412 (بدّل ah وal) — والـ 48 bit العليا من rax لازم تفضل زي ما هي. مسموحلك تستخدم bl كمساعد. (ده بالظبط اللي htons بيعمله لرقم الـ port!) swap16: ; your code here ret swap16: mov bl, al ; save the low byte mov al, ah ; low <- high mov ah, bl ; high <- saved low ret خلّي الـ 32 bit العليا من rax = 0 والسفلى زي ما هي، في instruction واحدة (+ ret). ممنوع تستخدم and. clear_hi: ret clear_hi: mov eax, eax ; 32-bit write zero-extends ret
