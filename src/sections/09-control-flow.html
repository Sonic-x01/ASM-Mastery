التحكم في التدفق: Jumps وConditions وLoops وSwitch

الـ CPU عنده أداة واحدة للتحكم: تغيير RIP. كل if وwhile وfor وswitch في الدنيا بيتحول لـ cmp + jump. لما تتعلم تشوف الـ patterns دي، هتبص على الـ graph في IDA وتعرف فورًا "دي loop، ودي if-else، وده switch".

الـ Jumps jmp · jcc

jmp label = goto (من غير شرط). jcc label = اقفز لو الشرط متحقق، والشرط بيتقرا من الـ flags (اللي سابتها آخر cmp أو test أو أي عملية حسابية). الـ jumps مش بتغير الـ flags.

الـ if/else: الـ compiler بيعكس الشرط pattern #1

في C بتكتب "لو الشرط، اعمل كذا". في Assembly الأسهل "لو عكس الشرط، اقفز فوق الكود". فـ if (score >= 90) بتبقى cmp score, 89 + jle (اقفز لو ≤ 89). عوّد نفسك تعكس الـ jump وإنت بتقرا. اضغط ⧉ Graph على أي tab:

int grade(int score) { if (score >= 90) return 'A'; else if (score >= 75) return 'B'; return 'F'; } int in_range(int a, int b) { return a > 0 && b < 10; }
⚡

Short-circuit (&& و||)

a > 0 && b < 10: لو الشرط الأول فشل، التاني مبيتحسبش خالص — قفزة مباشرة للـ "false". شوف in_range في -O0 وMSVC: سلسلة jumps كلها رايحة لنفس الـ label. أما gcc -O2 حسب الاتنين بـ setcc وعمل and (مسموح لأن مفيش side effects).

🚀

Branchless: setcc وcmovcc

setl al = al = (a < b) (0 أو 1). cmovl eax, ecx = if (a < b) eax = ecx من غير jump. الـ CPU بيحبهم لأن الـ branch prediction الغلط غالي. لما تشوفهم اقراهم كـ ternary: x = cond ? a : b.

max2: ; rdi = a, rsi = b ; --- version 1: branch --- mov rax, rdi ; assume a is the max cmp rdi, rsi jge .done1 ; if (a >= b) keep a (signed!) mov rax, rsi ; else take b .done1: mov rbx, rax ; keep the result ; --- version 2: branchless --- mov rax, rdi cmp rdi, rsi cmovl rax, rsi ; if (a < b) rax = b setl cl ; cl = (a < b) ? 1 : 0 ret

الـ Loops pattern #2: الـ back-edge

أي jump لورا (لعنوان أصغر) = loop. في الـ graph بيبان سهم راجع لفوق. الـ compilers بيحبوا شكل الـ do-while (الشرط تحت) لأنه jump واحد في كل لفة، فبيحوّلوا الـ for/while لـ: "لو مش هندخل خالص اقفز للنهاية، وإلا loop بالشرط تحت" (اسمها loop rotation):

loop_top: cmp ecx, edx jge loop_end ; condition at the top ; ... body ... inc ecx jmp loop_top ; back-edge loop_end: ret cmp ecx, edx jge loop_end ; guard: skip if 0 iterations loop_body: ; ... body ... inc ecx cmp ecx, edx jl loop_body ; condition at the bottom loop_end: ret

شوف loop حقيقية من gcc، وشوف clang عمل إيه بنفس الكود — شال الـ loop خالص واستبدلها بمعادلة n(n+1)/2 (مكتوبة بشكل ملتوي عشان تتفادى الـ overflow). الـ optimizers أذكى مما تتخيل، فمتتوقعش إن شكل الكود هيطابق الـ source:

int sum_to(int n) { int s = 0; for (int i = 1; i <= n; i++) s += i; return s; }
🔁
loop وjrcxz

loop label = dec rcx + jnz label في instruction واحدة (ومن غير ما تغيّر الـ flags). الـ compilers الحديثة مش بيستخدموها لأنها بطيئة، بس هتشوفها كتير في الـ shellcode والكود المكتوب بإيد (بسبب حجمها: 2 bytes). jrcxz = اقفز لو rcx = 0، بتتحط قبل الـ loop عشان تتفادى 2⁶⁴ لفة لو rcx بدأ بصفر.

الـ switch والـ Jump Tables pattern #3

لما الـ cases كتير ومتقاربة، الـ compiler بيعمل جدول عناوين ويقفز للعنوان رقم cmd مباشرة: jmp [table + cmd*8]. ده بالظبط شكل الـ command dispatcher في أي RAT أو backdoor: الـ C2 يبعت رقم الأمر، والـ switch يوديه لـ handler:

void cmd_shell(void); void cmd_upload(void); void cmd_download(void); void cmd_sleep(void); void cmd_info(void); void cmd_exit(void); void dispatch(int cmd) { switch (cmd) { case 0: cmd_shell(); break; case 1: cmd_upload(); break; case 2: cmd_download(); break; case 3: cmd_sleep(); break; case 4: cmd_info(); break; case 5: cmd_exit(); break; } }
🔬
إزاي تحلل backdoor dispatcher

(1) لاقي الـ indirect jump (jmp rax / jmp [x+rcx*8]). (2) لاقي الـ bounds check قبله (cmp …, 5 ⇐ 6 أوامر). (3) IDA غالبًا بيعرف الجدول ويكتب switch 6 cases — لو مقدرش، اقرا الجدول بإيدك. (4) ادخل كل handler وسمّيه حسب الـ APIs اللي بيستخدمها (CreateProcess ⇐ shell، WriteFile ⇐ upload…). ده بيديك قايمة capabilities الـ malware كاملة.

🎬 نفس الـ dispatcher متحرك: أمر جاي من سيرفر الـ C2، الـ bounds check، قراية الجدول، والقفزة للـ handler — وكمان إيه اللي بيحصل لو الأمر غلط:

لما الـ cases متباعدة (زي 1، 100، 5000) الـ compiler بيستخدم سلسلة مقارنات أو binary search (شجرة من cmp وjg) بدل الجدول. والـ bt trick من المرحلة اللي فاتت للقيم الصغيرة المتفرقة.

section .data table: dq handler0, handler1, handler2, handler3 section .text dispatch: ; rdi = command number cmp rdi, 3 ja .bad ; unsigned bounds check lea rdx, [rel table] jmp [rdx+rdi*8] ; indirect jump through the table .bad: mov eax, -1 ret handler0: mov eax, 100 ret handler1: mov eax, 200 ret handler2: mov eax, 300 ret handler3: mov eax, 400 ret
